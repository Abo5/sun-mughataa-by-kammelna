## ٢. ⭐⭐ التثبيت — أعقد جزء

`UiListView` الأساس يثبّت **بالاستنساخ** ([`ui-spec/01`](../ui-spec/01-إطار-القوائم.md)).
الموجز يضيف فوقه:

| الدالّة | الدور |
|---|---|
| `TemplateKeepsWhenPinned` @`0x52AFDF0` | هل يحافظ القالب على شكله عند التثبيت؟ يرجع `bool?` عبر `TemplateStrip` |
| `TemplateUsesSeparatePrefab` @`0x52AFEA4` | **قالب منفصل للحالة المثبَّتة** |
| `KeepPinnedDatumInList` @`0x52B04F0` | هل يبقى الأصل في القائمة؟ |
| `GetPinnedHeight` @`0x52B0698` (556B) | ارتفاع الرأس المثبَّت |
| `GetPinnedTopOffset` @`0x52B05EC` | إزاحة التمرير المقابلة |
| `MorphsInPlaceIndex` @`0x52B0344` · `NudgeIndex` @`0x52B0244` | تحوّل في المكان مقابل إزاحة |

> ⭐ **ثلاثة أنماط تثبيت مختلفة**: قالب يحافظ على شكله · قالب منفصل · **تحوّل في المكان**
> (`MorphsInPlaceIndex`). هذا أغنى بكثير من تثبيت الإطار الأساس.

`ServerTogglePin` @`0x52AF8F4` ✅ — يبني `Action<bool>` **مرّتين** (نجاح/فشل) ويرسل الطلب،
مع مقارنة `cmp w10, w9` (🟡 على الأرجح حدّ عدد المثبَّتات).
والمسارات الخادميّة: `POST api/Clans/feed/{0}/pin` · `unpin` · `like` · `unlike`
(موثّقة في [٠٣](03-العشائر-والإشراف.md)).

## ٦. ⭐ قائمة إعادة البناء

1. **فرّق بين مدخلات عاديّة وغرف حيّة** بقوالب مختلفة، واشترط جاهزيّة القوالب قبل العرض.
2. **الترقيم بالمُعرّف (cursor) لا بالصفحة** — أرسل أقدم معرّف واطلب ما قبله.
3. **خفّ الطلبات زمنيًّا** بـ`realtimeSinceStartup` — وإلّا أغرقت الخادم عند التمرير السريع.
4. **ثلاثة أنماط تثبيت**: قالب محافظ · قالب منفصل · تحوّل في المكان.
5. **حدّث أشرطة التقدّم في مكانها** لا بإعادة بناء المدخل.
6. اجعل ملف التنقّل (`OpenX`) **بلا منطق** — أسهل ملف في المشروع، وأكثره استقرارًا.

## ٦ب. ⭐⭐⭐ `ReconcileServerFeed` مفكوكةً @`0x52AE26C` (3,192B) ✅

> **أكبر دالّة في هذا الفصل، وقد فُكَّت الآن بالكامل.**
> التوقيع: `public void ReconcileServerFeed(IReadOnlyList<ClanFeedEventDataHolder> incoming)`.
> ثلاث مراحل، وفيها **حِرزان** (exemptions) لا يمكن استنتاجهما من الاسم.

### الحقول المستعملة
| المرجع | المعنى |
|---|---|
| `this[0x98]` | `List<ClanFeedEventDataHolder>` — المدخلات المحليّة (`Items`) |
| `holder[0x18]` | `ClanFeedModel Model` — **`null` في الغرف الحيّة** |
| `model[0x10]` | `long Id` |

### المرحلة ١ — جمع معرّفات الخادم وأصغرها @`0x52AE4DC`–`0x52AE5D8`
```csharp
var serverIds = new HashSet<long>();          // 0x52AE3F8
long minServerId = long.MaxValue;
foreach (var d in incoming) {
    if (d == null || d.Model == null) continue;          // 0x52AE5A0 · 0x52AE5A8
    serverIds.Add(d.Model.Id);                          // 0x52AE5C0
    minServerId = Math.Min(minServerId, d.Model.Id);    // csel x20, x8, x20, lt @0x52AE5D4
}
```

### المرحلة ٢ — الحذف، بحِرزَين @`0x52AE678`–`0x52AE7C0`
```csharp
var toRemove = new List<ClanFeedEventDataHolder>();
foreach (var local in Items) {
    if (local == null)            continue;
    if (local.Model == null)      continue;      // ← الحِرز الأوّل  @0x52AE6DC
    if (local.Model.Id < minServerId) continue;  // ← الحِرز الثاني  @0x52AE6E4 (b.lt)
    if (serverIds.Contains(local.Model.Id)) continue;   // 0x52AE700
    toRemove.Add(local);
}
foreach (var d in toRemove) RemoveItem(d);       // UiListView.RemoveItem @0x52AE7B0
```

> ⭐⭐⭐ **الحِرزان هما جوهر صحّة هذه الدالّة، وإسقاط أيٍّ منهما عطب مرئيّ فوريّ:**
>
> **١) `Model == null` ⇒ لا يُحذَف أبدًا.** هذه هي **الغرف الحيّة** — مدخلات يصنعها العميل
> محليًّا عبر `ClanFeedEventDataHolder.LiveTournament(…)` و`LiveGame(…)`، وهما يستعملان المُنشئ
> الخاصّ `(index, sortDate, tournamentRoom, gameRoom)` **بلا `Model`**. الخادم لا يعرف بها،
> فلو لم يُحرَز لحُذفت بطولتك الجارية من الموجز عند أوّل تحديث.
>
> **٢) `Id < minServerId` ⇒ لا يُحذَف أبدًا.** الموجز مُرقَّم بمؤشّر (cursor) لا بصفحات، والاستجابة
> تحمل **نافذة واحدة** من المعرّفات. كل ما هو أقدم من أصغر معرّف في الاستجابة يقع خارج النافذة،
> وغيابه من `serverIds` **ليس دليل حذف**. بلا هذا الشرط لكان كل تمرير إلى الأسفل يمسح
> ما سبق تحميله. هذا هو الفرق بين «مصالحة نافذة» و«مصالحة كاملة».

### المرحلة ٣ — الإضافة أو التحديث @`0x52AE860`–`0x52AE9BC`
```csharp
foreach (var d in incoming) {                       // عبر مُعدِّد واجهة (slot 0)
    if (d == null || d.Model == null) continue;      // 0x52AE96C
    var dc = new <>c__DisplayClass6_0 { d = d };     // 0x52AE8D0 · الحقل 0x10 @0x52AE954
    var existing = Items.Find(dc.<ReconcileServerFeed>b__0);   // 0x52AE9A0
    if (existing == null) AddFeed(d);                          // 0x52AE864
    else                  existing.UpdateModel(d.Model);       // 0x52AE9B8
}
SeedPinFromData();                                  // 0x52AEA44 — دائمًا
```
`mov w22, #0x12` @`0x52AE9C4` ثم `cmp w22, #0x12; b.eq` @`0x52AEA34` — سنتينل مترجم
(هدف `leave` من `try/finally`) لا شرط حقيقيّ ⇒ **`SeedPinFromData` تُنفَّذ دائمًا بعد الحلقة.**

### المُطابِق — `<ReconcileServerFeed>b__0` @`0x52B1D40` (204B)
```csharp
bool b__0(ClanFeedEventDataHolder local) {
    long? id = (local.Model != null) ? local.Model.Id : (long?)null;   // Nullable<long> @0x38C8F74
    return id.HasValue && id.Value == this.d.Model.Id;                 // and w0, w8, w9 @0x52B1DF0
}
```
> ⭐ المطابقة **بـ`Model.Id` حصرًا** — لا بالفهرس ولا بالتاريخ.
> ولأنّها تعيد `false` عند `Model == null`، فالغرفة الحيّة **لا تُحدَّث أبدًا** كذلك:
> تُحرَز من الحذف ومن التحديث معًا، وتُدار وحدها عبر `HasLiveRoom`/`RemoveLiveRoomById`.

### مسار ثانٍ — `Items == null` @`0x52AE440` → `0x52AEA4C`
إن كانت القائمة المحليّة معدومة، تُتخطّى المرحلتان ١ و٢ بالكامل ويُبنى المحتوى إلحاقًا فقط،
مع **بوّابة `ShouldDisplay` لكل مدخل** (`0x52AEB64` ثم `tbz w0,#0` → تخطٍّ).
هذا نصف حجم الدالّة تقريبًا، وهو سبب كِبَرها لا وجود منطق مكرَّر.

### خلاصة إعادة البناء
| القاعدة | القيمة |
|---|---|
| هويّة المدخل | `Model.Id` (`long`) |
| الغياب من الاستجابة ⇒ حذف؟ | **فقط إن كان `Id >= min(serverIds)`** |
| مدخل بلا `Model` | محرَّز من الحذف والتحديث معًا (غرفة حيّة) |
| الموجود مسبقًا | `UpdateModel(d.Model)` — **تحديث في المكان لا إعادة بناء** |
| الجديد | `AddFeed(d)` (وفيه `SortedInsertIndex`) |
| بعد كل مصالحة | `SeedPinFromData()` دائمًا |
| ترتيب المراحل | اجمع → احذف → أضِف/حدِّث → أعِد بذر التثبيت |
