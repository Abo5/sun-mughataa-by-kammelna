## ٣. نموذج المراحل (من `mass_events`) ✅

`MassEventModel`: `Id` · `Game` · `AssignedServerId` · `AssignedRoomId` · `Name` · `Organizer` ·
`IsRegisterByCode` · `AvailabilityDate` · `StartingDate` · `RegistrationDeadline` · `FinishDate` ·
`Theme` · `PhysicalFinalTitle/Description` · `Prizes[]` · `SponsorBanners[]` · **`Stages[]`** ·
`Images[]` · `ActiveStage` · `IsRegistrationOpen`.

**`MassEventStageViewModel`**:

| الحقل | الإزاحة | ملاحظة |
|---|---|---|
| `Id` | 0x10 | **يطابق `ast`** |
| `Type` | 0x14 | `MassEventStageType` |
| `FilterValue` | 0x18 | `int?` — عتبة الفلتر |
| `MaxTrails` | 0x20 | `int?` — عدد المحاولات |
| `StartingDate` / `FinishDate` | 0x28 / 0x30 | |
| `TrailsRefreshWindow` | 0x38 | `TimeSpan` |
| `PhysicalFinalTitle/Description` | 0x40 / 0x48 | |
| `PlayWindows` | 0x50 | `List<MassEventPlayWindowViewModel>` (`StartingTime`, `FinishTime`, `IsTimeWithinWindow`) |
| `TournamentSize` | 0x58 | |
| `Prize` / `SecondaryPrize` / `TertiaryPrize` | 0x5C / 0x60 / 0x68 | |

**`MassEventStageType`** ✅:
`ConstantPlayersFilter=0 · ConstantPointsFilter=1 · PlayersRatioFilter=2 · TournamentWinnersFilter=3 · Physical=4`

> ⭐ **آلية الترقية**: نوع المرحلة + `FilterValue` (ثابت من JSON) يحدّدان المعيار،
> و**الخادم** يحسب عتبة العبور وينشرها حيًّا في **`afv`**، وحالة اللاعب تصل في **`enr`**.

## ٤. ⭐ حالة اللاعب — أمر نطاق `mpr` ✅

`MassTournamentServerConnector.LoadPlayerState` @`0x4F02830` → **`mpr`** بلا حمولة.
`MassTournamentPlayerState.FromSfsObject` @`0x4EFF75C`:

| المفتاح | الحقل | الإزاحة |
|---|---|---|
| `ir` | `IsRegistered` | 0x10 |
| `ls` | `LastStageReached` | 0x14 |
| `tkt` | `TriesLeft` | 0x18 |
| **`ntkt`** | `NextTicketTime` (`DateTime?`، الافتراضي `Now`) | 0x20 |
| `msp` | `ChampionshipPoints` | 0x28 |
| **`enr`** | `NextStageEligibility` | 0x2C |
| `ui` | `UniqueId` | 0x30 |
| `eb` | `EventBio` | 0x38 |

**`MassEventNextStageEligibility { NotEligible=0, Eligible=1, EligibleToReserve=2 }`** ✅
— **هذا هو قرار الترقية كما يراه العميل.**
(`TournamentEligibilityStatus` نظيرتها: `Eligible=0 · NotEligible=1 · EligibleToReserve=2` — **انتبه للاختلاف في القيمتين ٠ و١**.)

> 📌 **ملاحظة تقاطعية**: مفتاح `ntkt` يعيش **هنا** — في حالة لاعب البطولة الجماهيرية.
> وهذا يؤكّد النتيجة السابقة في [أرشيف البلوت](../baloot-spec/15-تدقيق-ARM64.md) بأن
> `OfflineGameController.BuildRoundState` **لا يكتب `ntkt`**؛ المفتاحان في عالمين مختلفين.

### ⭐ `SFSCommands.ManageMass` — يكشف نموذج العنقود ✅

```
COMMAND = "mme" ; ACTION = "act"
  1 ACTION_EXTEND_STAGE        + em   (دقائق التمديد)
  2 ACTION_MANAGE_CLUSTER      + ca   (1=ENTER, 2=FORCE_START, 3=CANCEL)
  3 ACTION_FIND_TOURNAMENT     + tn   (اسم البطولة)
  4 ACTION_GET_PLAYER_INFO
  5 ACTION_ADD_TRIES           + tta  → استجابة utkt
  6 ACTION_ADD_PLAYER_POINTS   + pta  → استجابة msp
```

> **العنقود (cluster)** كيان يُدخَل / يُجبَر بدؤه / يُلغى؛ ومتغيّر `acst` يحمل وقت بدئه؛
> و`cz`/`cl`/`cid` في `TournamentData` تصف سعته وانتماءه.
> 🟡 **شروط الانتقال بين العناقيد خادمية ولم تُستخرَج.**

## ٦. دورة حياة الـHub ✅

* **`Init`** @`0x4F00B2C`: `ExtractMassId(payload)` @`0x4F01440` (يقتطع بعد فاصل في نصّ رابط عميق؛
  يرمي `InvalidOperationException("Mass Tournament payload is empty.")`)
  → إن `room.IsMassTournament()` ⇒ `SetReady()` وإلا `MassTournamentManager.JoinRoom(...)`.
* **`HandleRegistrationCode`** @`0x4F01580`: `payload.Split(...)` → `MassTournamentRegistrationSheet`
  → `RegisterInTournament(code, …)` @`0x4F00360` → `SFS.ParticipateMassTournament` (`pt` + `reg_code`).
* **`OnRoomChanged`** @`0x4F01E4C`: `MarkNotReady` و`Unbind`، ويستعيد الغرفة من
  `UserInfo.LastJoinedMassTournamentRoomId`.
* **`IsWaitingToStart`** @`0x4F0254C`: `if (GetActiveStageId() != 0) return false; return GetActiveStage().StartingDate > Now;`
* **`GetActiveStage`** @`0x4EFB4DC` = `GetCachedMassEvent(liveData.Id).Stages[بحث بـ ast]`.
* **`GetUpcomingStage`** @`0x4EFCC38` = المرحلة التالية لـ`ast`.
* **`IsFinalStage()`** @`0x4F02914` = **`GetUpcomingStage() == null`** ✅.
* **`GetActivePlayWindow`** @`0x4EFCB70` = `GetActiveStage().PlayWindows[apw.Value]`.
