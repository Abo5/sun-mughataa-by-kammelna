## ٣. ⭐ قائمة إعادة البناء

1. **اجعل صفحة المتجر مدفوعة بالخادم**: قائمة أقسام، كل قسم بنوعه ومحتواه، مع `templateId`.
   ⇒ تغيير الترتيب والمحتوى عن بُعد بلا تحديث.
2. **ثمانية أنواع أقسام** (`Banners` … `Bundles`) — احفظ الترقيم إن أردت توافقًا.
3. **ثلاث حالات لزرّ البطاقة**: اشترِ · فعّل · حالة — تُقرَّر بـ`IsActiveItem` والملكية.
4. **احجب الطلب عند عدم كفاية الرصيد** (نمط `BuyCardPopup`)، **ولا تكتفِ به** —
   أعد التحقّق خادميًّا.
5. **افصل «المتاح» عن «المختار»** في ورقة الإضافات.

## ٣ب. ⭐⭐⭐ `Populate` مفكوكةً @`0x4FE8184` (6,772B) ✅

> `public void Populate(StoreHomePageViewModel sections)` على
> `StoreHomePageGroup : UiGridView<StoreDataHolder, ListViewItem<StoreDataHolder, int>>`.

### 🛑 تصحيحان لما سبق في هذا الفصل
**١) المُهيِّئات العشرة ليست «موزَّعًا عليها» — بل مُضمَّنة (inlined).**
كلّها `public static StoreDataHolder Init…(…, int i)` — ساكنة غير ظاهريّة، وعند مسح
امتداد `__TEXT` كلّه لم تُوجَد لأيٍّ منها **ولا مرجع واحد**: لا `bl` ولا `b` (نداء ذَيليّ)
ولا فتحة `Method$` في `ScriptMetadataMethod`. وبما أنّها ساكنة غير ظاهريّة، فالقاعدة المعتمدة
في هذا الأرشيف تنطبق عليها بلا استثناء.
وفي المقابل يحتوي `Populate` على **١٣ موضع `StoreDataHolder.SetTemplate`** @`0x4FF3B6C`:
`0x4FE86C8` · `0x4FE8858` · `0x4FE8920` · `0x4FE8A24` · `0x4FE8BC8` · `0x4FE8C98` · `0x4FE8E34`
· `0x4FE8F04` · `0x4FE90F0` · `0x4FE91AC` · `0x4FE9420` · `0x4FE94C8` · `0x4FE9674`.
> ⇒ **clang ضمّن المصانع العشرة كلّها داخل `Populate`، وهذا سبب حجمها لا وجود منطق فيها.**
> تواقيعها تبقى المرجع الأفضل لفهم كل فرع، لكنّها **ليست نقاط استدعاء**.

**٢) مفتاح التجميع محسوم:** `GroupBy` @`0x4FE8D80` يأخذ
`Func<StoreItem, int> = <Populate>b__0_6` @`0x4FF3554`، وجسمها ثلاث تعليمات:
`ldr w0, [x1, #0x68]` ⇒ **`StoreItem.pack`** (`dump.cs` — `<pack>k__BackingField; // 0x68`).
> ⭐ ⇒ **ظهور البطاقات يُجمَّع في «رُزَم» (packs)**: كل رزمة تصير مدخلًا واحدًا في الشبكة
> عبر `Select(b__7)` @`0x4FF369C` (٤٣٢B — أكبر لامدا، تبني مدخل الرزمة).

### التوزيع — بحث ثنائيّ على `section.type` (الحقل `0x18`)
```asm

0x4FE8568  cmp  w8, #2 ; b.le  → 0x4FE871C
```

> (`InitPatternItem` @`0x4FF33A8`)، ولا فرع له في `Populate` — فيصل إلى الفرع الافتراضيّ
> ويرمي `ArgumentOutOfRangeException`.**
> وبما أنّ الأقسام تُعدَّد في حلقة واحدة، فإنّ الاستثناء **يُسقط بناء الصفحة كلّها**:

### شكل كل فرع
الأذرع الستّة ذات القوائم تتبع النمط نفسه:
```csharp
if (section.featuredXxx.IsNullOrEmpty()) continue;            // ArraysExtensions.IsNullOrEmpty<int>
var items = <المصدر>.Where(d => section.featuredXxx.Contains(d.id))   // b__1/b__3/b__5/b__8
                    .ToList();
```

المرشِّحات `b__1`/`b__3`/`b__5`/`b__8` كلّها في `<>c__DisplayClass0_1` وكلّها بنفس الجسم:
ذيلها `b #0x33FC6D0` = `List<int>.Contains`، أي `section.featuredXxx.Contains(item.id)` حرفيًّا.

### العدّاد الجاري
`<>c__DisplayClass0_0` يحمل `int index` @`0x10` و`StoreHomePageViewModel sections` @`0x18`.
وكل لامدا بناء (`b__2` @`0x4FF3584` مثلًا) تفعل:
```asm
ldr w21, [x0, #0x10]     ; index
add w8,  w21, #1
str w8,  [x0, #0x10]     ; index++   ← مشترك بين كل الأقسام
…
str w21, [holder, #0x10] ; holder.index = القيمة القديمة
```
> ⭐ **`index` عدّاد جارٍ واحد عبر الأقسام كلّها** — لا يُصفَّر عند حدود القسم.
> فترتيب الشبكة النهائيّ هو ترتيب الخادم مسطَّحًا، والعناوين تأخذ أرقامًا في التسلسل نفسه.

### البانرات
```csharp
banners.Where(b => b.image != null && b.image.type == ImageCacher.BannerSize.Wide)   // b__0_0
       .ToList()
       … .First()                                             // 0x4FE9088
```
`b__0_0` @`0x4FF34FC`: `ldr x8,[x19,#0x38]` = `banner.image` ثم `ldr w8,[x8,#0x20]; cmp w8,#1`
⇒ الحقل `type` من `ImageInfoModel<BannerSize> : FileInfoModel` (`url`@`0x10` · `lastModified`@`0x18` · `type`@`0x20`)
و`enum BannerSize { Normal = 0, Wide = 1 }`.
> ⭐ **قسم البانرات يعرض البانرات العريضة فقط**، ويأخذ **أوّلها** (`First` لا `FirstOrDefault`)
> ⚠️ ⇒ قسم بانرات كلّه `Normal` يرمي `InvalidOperationException`.
> والفرع الآخر يستعمل `banners.Count` و`InitBannerList` لعرض القائمة كاملة.

## ٦. ✅ حقول نماذج صفحة المتجر

`[CS:]` من `dump.cs` — الإزاحات بتعليقات `// 0xNN` الأصليّة، والثلاثة `[Serializable]` بمُلحِّنات JSON.

### `StoreBannerViewModel` (TypeDefIndex 2520) ✅
```csharp

    string          id;              // 0x10   ⚠️ نصّ لا int
    string          name;            // 0x18
    RoutingCommand  routingCommand;  // 0x20   ⭐
```

> ⭐⭐ **البانر ليس صورةً فقط، بل `RoutingCommand` كامل**: الخادم يرسل **أمر تنقّل مرقّمًا**
> + وسيطًا نصّيًّا + لعبةً اختياريّة. `[ENUM:]` `RoutingCommand` تعداد ضخم بقيم ثابتة،
> ومنه في نطاق المتجر وحده:
> ```
> OpenCustomURL=3 · Store=7000 · MainStore=7001 · CardsStore=7002 · RoomThemesStore=7003
> SubscriptionsStore=7004 · GoldenCardsStore=7005 · BuyProduct=7006
> PresentRedeemCodeSheet=7007 · BuyOffer=7009
> ```
> ⇒ **بانرٌ واحد من الخادم يستطيع أن يفتح أي شاشة، أو يبدأ شراء منتج (`7006`) أو عرضٍ موقَّع
> (`7009`) مباشرةً، أو يفتح ورقة استرداد الأكواد (`7007`)، أو رابطًا خارجيًّا (`3`).**
> **أقوى سطح تحكّم عن بُعد في المتجر كلّه.** 🚩 واجعله مُقيَّدًا بقائمة أوامر مسموحة في نسختك،
> ولا تمرّر `routingParam` إلى فتح URL بلا تصفية.
> ⚠️ لاحظ أن `7008` غائب عن التعداد بين `7007` و`7009` — فجوة مقصودة أو أمرٌ أُزيل.
> ✅ و`image.type` هو الحقل الذي تُصفّي به `Populate` البانرات `Wide` ([§٣ب](#٣ب--populate-مفكوكةً-0x4fe8184-6772b-)).
