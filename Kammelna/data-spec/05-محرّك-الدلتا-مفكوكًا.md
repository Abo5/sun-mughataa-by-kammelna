# ٠٥ — محرّك الدلتا مفكوكًا: القطبيّة الحقيقيّة

[↩ الفهرس](README.md)

> **هذا الفصل يُصحّح [الفصل ٠١ §٣](01-طبقة-البيانات.md) في أهمّ نقطة في طبقة البيانات كلّها.**
> الموثّق هناك أنّ `ApplyDelta` تختار بين الدمج والاستبدال بحسب `cache.IsValid()`.
> **لا وجود لهذا الفرع في الثنائي.** `ApplyDelta` لا تستدعي `Replace` إطلاقًا، والفرع الحقيقيّ
> في **مسار REST** وشرطه **المؤشّر** لا الصلاحيّة. وكلّ عنوان أدناه مفكوكٌ من كود الآلة،
> وقد أُعيد التحقّق من كلّ دعوى حاملة بتفكيك ثانٍ مستقلّ.

**سُلّم اليقين**: ✅ مُثبت من كود الآلة · 🟡 استنتاج · ⚪ نصّ داخل التطبيق

---

## ✅ ما تُحقِّق منه مرّتين

| # | الادّعاء | العنوان | النتيجة |
|---|---|---|---|
| ١ | `ApplyDelta` تنادي `Merge` **بلا شرط** ولا تنادي `Replace` قطّ | `0x328BAC4` | ✅ `bl #0x328bcec` بلا أيّ فرع قبله |
| ٢ | مستدعو `Replace` في الثنائي كلّه = **٣**، كلّهم `<FetchSince>b__0` | `0x31D3190` · `0x31D3304` · `0x31D3478` | ✅ صفر مستدعٍ خارج مسار REST |
| ٣ | **القطبيّة**: `cursor == 0 ⇒ Replace` · `cursor != 0 ⇒ Merge` | `0x31D312C`+`0x31D3130` | ✅ `ldr x8,[x19,#0x18]` ثمّ `cbz x8` |
| ٤ | `IsValid()` **لا تختار فرعًا** — تحكم كتابة `LastUpdate` وحدها | `0x328BAA4` · `0x328BAC8` | ✅ `cbz w23` يتخطّى كتلة `set_LastUpdate` فقط |
| ٥ | حرس لم يُوثَّق: `if (cache.Model == null) return;` | `0x328BA40` | ✅ `get_Model` ← `cbz x0` إلى مسار `ret` |
| ٦ | `FetchSince` **تصفّر المؤشّر قسرًا** إن كان النموذج معدومًا | `0x328BC24` | ✅ `str xzr, [x20, #0x18]` |
| ٧ | **`Merge` تكتب `ServerCursor` أيضًا** — بقفزة ذيليّة | `0x328BDF0` | ✅ `b #0x4380134` ⇒ `set_ServerCursor` |
| ٨ | `onApplied` مشروطٌ بـ`HasChanges` | `0x328BB14` · `0x328BB18` | ✅ `cbz w0` ⇒ خروجٌ بلا إشعار |
| ٩ | `ContentSinceRequest.Method` = **`GET`** | `0x4492A48` | ✅ `mov w0,#0 ; ret` (و`HttpMethod.GET = 0`) |
| ١٠ | الطرد في `InMemoryCacheAssetLoader` = **FIFO** | `0x2E7255C`–`0x2E7257C` | ✅ `cmp` ثمّ `b.le` ثمّ `mov w1,#0` ⇒ `RemoveAt(0)` |

## ١. ⭐⭐ القطبيّة — الجدول الذي يجب أن يُحفظ

| المسار | الدالّة | الشرط | الفرع |
|---|---|---|---|
| **push** (SignalR) | `ApplyDelta` @`0x328B9C4` | — بلا شرط | **`Merge` دائمًا** |
| **pull** (REST) | `<FetchSince>b__0` @`0x31D30CC` | `cursor == 0` | **`Replace`** — استبدال كامل |
| **pull** (REST) | `<FetchSince>b__0` @`0x31D30CC` | `cursor != 0` | **`Merge`** — دمج تزايديّ |

التعليمتان الفاصلتان:
```
0x31D312C  ldr   x8, [x19, #0x18]   ; x19 = <>c__DisplayClass10_0 ، و+0x18 = cursor
0x31D3130  cbz   x8, #0x31d317c     ; cursor == 0 ⇒ اقفز إلى فرع Replace
0x31D3150  bl    #0x328bcec         ; الساقط: Merge            (cursor != 0)
0x31D3190  bl    #0x328bdf8         ; هدف القفزة: Replace      (cursor == 0)
```

**أربع نسخ مستقلّة، قطبيّة واحدة**: النسخة المشتركة `__Il2CppFullySharedGenericType` @`0x31D3528`
تحمل النمط نفسه حرفيًّا (`0x31D35B4 ldr x8,[x19,#0x18]` ثمّ `cbz`).

### ⭐ ولماذا هذه القطبيّة **آمنة**؟ — التصفير القسريّ
```
0x328BC1C  bl    #0x4380188        ; cache.Model
0x328BC20  cbnz  x0, #0x328bc28
0x328BC24  str   xzr, [x20, #0x18] ; ⭐ cursor = 0 إن كان النموذج المحليّ معدومًا
```
`FetchSince` **تتجاهل المؤشّر المُمرَّر وتصفّره** متى كان القرص خاليًا. ⇒ **أوّل جلب بعد التثبيت
أو بعد `Clear()` يسلك `Replace` حتمًا** ولو نُودي بمؤشّر غير صفريّ. هذا هو الأمان المعماريّ
الذي يجعل «`cursor != 0 ⇒ Merge`» قرارًا سليمًا لا مخاطرة.

## ٢. `ApplyDelta` مفكوكةً ✅ @`0x328B9C4` (408B)

```csharp
void ApplyDelta(string payloadJson) {
    var cache = _cacheOf();                        // +0x20 ; معدومٌ ⇒ NRE @0x328BA14
    if (cache == null) return;                     // 0x328BA28
    if (cache.Model == null) return;               // ⭐ 0x328BA40 — حرس لم يُوثَّق
    var delta = JsonConvert.DeserializeObject<ContentDeltaModel<TModel,TId>>(payloadJson);
    if (delta == null) return;                     // 0x328BA6C / 0x328BA8C
    bool wasValid = cache.IsValid();               // 0x328BAA4 → w23
    Merge(cache, delta);                           // 0x328BAC4 — بلا شرط
    if (wasValid) cache.LastUpdate = DateTime.Now; // 0x328BAC8 cbz w23
    if (ContentDeltaMerge.HasChanges(delta))       // 0x328BB14
        _onApplied?.Invoke();                      // +0x30 ، br x2 @0x328BB40
}
```

ثلاث دلالات لا تظهر من الاسم:

1. 🛑 **دفعة push قبل أوّل جلب تُهمَل صامتةً** (الحرس في `0x328BA40`) ولا يُخزَّن مؤشّرها.
   ⇒ **الاعتماد على push وحده لا يُنشئ الحالة**؛ `EnsureFresh`/`CatchUpAll` إلزاميّ للتأسيس.
2. 🛑 **الدمج push لا يُزيل «قذارة» الكاش**: إن كان غير صالح عند وصول الدلتا فالبيانات تُدمَج
   و`LastUpdate` **لا يُرفَع** ⇒ `IsValid()` يبقى `false` ⇒ أوّل `EnsureFresh` تالٍ يذهب للشبكة.
   **هذه هي وظيفة `IsValid()` الحقيقيّة هنا** — لا اختيار فرع.
3. ⚠️ **`onApplied` لا يُطلَق إن لم يكن في الظرف شيء** (`HasChanges`)، لكن `HasChanges` تقيس
   **عدد عناصر الظرف** لا تغيّرًا فعليًّا ⇒ ظرفٌ فيه عنصرٌ مطابق للموجود **يُشعل الإشعار**.

## ٣. `<FetchSince>b__0` مفكوكةً ✅ @`0x31D30CC` (364B)

```csharp
void <FetchSince>b__0(KammelnaResponseModel<ContentDeltaModel<TModel,TId>> response) {
    if (response == null) throw NRE;                        // 0x31D3108
    if (!response.Succeeded) { onDone?.Invoke(false); return; }   // 0x31D3120 → 0x31D3174
    var delta = response.Data;                              // +0x30
    if (delta == null) { onDone?.Invoke(false); return; }    // 0x31D3128
    bool changed = (cursor == 0)                            // 0x31D3130
        ? Replace(cache, delta)                             // 0x31D3190
        : (Merge(cache, delta), HasChanges(delta)).Item2;    // 0x31D3150 / 0x31D3164
    cache.LastUpdate = DateTime.Now;                        // بلا شرط في هذا المسار
    if (changed) _onApplied?.Invoke();                      // 0x31D31E4
    onDone?.Invoke(true);                                   // br x3
}
```

⚠️ **فارقان دقيقان بين المسارين — احفظهما**:

| | push (`ApplyDelta`) | pull (`<FetchSince>b__0`) |
|---|---|---|
| كتابة `LastUpdate` | **فقط إن كان الكاش صالحًا سلفًا** | **دائمًا** عند النجاح |
| مصدر راية «تغيّر» | `HasChanges(delta)` = عدد عناصر الظرف | `Replace` ⇒ **مقارنة JSON فعليّة** · `Merge` ⇒ `HasChanges` |

## ٤. ظرف الدلتا — الموثّق سابقًا **صحيح**، مع إكمالات

`ContentDeltaModel<TModel,TId>`: `Upserts @+0x10` · `RemovedIds @+0x18` · `Cursor @+0x20`
(ثلاث قراءات مستقلّة من ثلاث دالّات، مطابقة لترتيب `dump.cs`) ✅

**`ContentDeltaMerge.Merge` @`0x2D393E0` (904B) مفكوكة كاملةً**: upsert-by-id
(`FindIndex` @`0x2D395C4` ⇒ `set_Item` @`0x2D394F8` أو `AddWithResize` @`0x2D39638`)
ثمّ `RemoveAll` @`0x2D396CC` بشرط `Count >= 1`.
* المُقارِن: `idOf(m).Equals(idOf(up))` (`Int32$$Equals` @`0x31D2C04`).
* شرط الحذف: `RemovedIds.Contains(idOf(m))` (`List<int>$$Contains` @`0x31D2624`).
* ⭐ **الحذف يُطبَّق بعد الترقية** ⇒ عنصرٌ ورد في `Upserts` و`RemovedIds` معًا **يُحذَف**.

### 🛑 و`Replace` ليس «الطريق الآخر» بل سلوكٌ مختلف جوهريًّا
| | `Merge` | `Replace` |
|---|---|---|
| `RemovedIds` | يُطبَّق | **يُتجاهل تمامًا** |
| كشف التغيّر | عدد عناصر الظرف | **إعادة تسلسل القائمتين إلى JSON ومقارنتهما نصًّا** (`0x31D6404`/`0x31D6414` ثمّ `op_Inequality` @`0x31D6424`) |
| القائمة المُسلَّمة للكاش | **نسخة** `new List<T>(current)` | **مرجع `delta.Upserts` نفسه** |
| `ServerCursor` | يُكتب (قفزة ذيليّة `0x328BDF0`) | يُكتب |

> 🚩 **كشف JSON النصّيّ حسّاسٌ لترتيب الخادم**: إعادة ترتيب العناصر بلا تغيير محتوى
> تُقرأ «تغيّرًا». وفي الاتجاه المقابل، تسليم **مرجع** `delta.Upserts` يعني أنّ أيّ تعديل
> لاحق على الظرف يمسّ الكاش.
> 🛑 وبذلك **تسقط دعوى «`Replace` هو الموضع الوحيد الذي يكتب المؤشّر»** — `Merge` يكتبه أيضًا،
> بقفزة ذيليّة `b` يُخفيها مسحُ `bl` وحده. (نفس فخّ [واجهة ٠٤](../ui-spec/04-طبقات-الضباب-والنوافذ.md).)

## ٥. كاش الأصول في الذاكرة = **FIFO** لا LRU 🛑

`CacheLoadedAsset` @`0x2E724DC`:
```
0x2E72558  ldr   w8, [x19, #0x18]   ; List.Count
0x2E7255C  ldr   w9, [x21, #0x10]   ; max
0x2E72560  cmp   w8, w9
0x2E72564  b.le  #0x2e72584         ; Count <= max ⇒ لا طرد
0x2E72578  mov   w1, #0             ; ⇒ RemoveAt(0) = الأقدم إدخالًا
```
* ⭐ **السعة الفعليّة ٢٠١ لا ٢٠٠** — الشرط `Count > max` يُقيَّم **قبل** `Add`.
* العدد ٢٠٠ له موضع بناء واحد: `mov w1,#0xc8` @`0x5099054`.
* **ثلاثة أدلّة سالبة تنفي LRU**: مسار القراءة (`<LoadAsset>d__7.MoveNext` @`0x45A36D8`، 660B)
  **لا يُعيد الترتيب ولا يُحدِّث ختمًا**؛ و`CachedAssetModel.Timestamp` ختمُ خادمٍ `readonly`
  للإبطال بالبيانات؛ و`UpdateLastAccessTime` يلمس **القرص** (وهو ما يُغذّي LRU الحقيقيّ في
  `CleanFolder` — انظر [الفصل ٠١](01-طبقة-البيانات.md)).
* `OnLowMemory` @`0x5098B28` و`ResetEnvironment` @`0x5098AB4` = `Clear()` كامل (كود متطابق حرفيًّا).

> ⇒ **في نسختك**: طردُ الأقدم إدخالًا يُخرج أصلًا مستعملًا بكثافة. إن أردت LRU في الذاكرة
> فأضِفه — الأصل لا يفعله.

## ٦. `onApplied` مقابل `onChanged` — الجدول الحاسم 🛑

حقول الـapplier من `.ctor` @`0x328B910`:
`+0x18 sincePath` · `+0x20 cacheOf` · `+0x28 idOf` · **`+0x30 onApplied`** · **`+0x38 onChanged`**

🛑 **تصحيح**: `ApplyDelta` و`<FetchSince>b__0` يُناديان **`onApplied` وحده** — لا
`{_onApplied(); _onChanged();}`. و`onChanged` يُنادى **حصرًا** من `ApplyChanged` @`0x328B9A4`.

| المفتاح | `onApplied` | `onChanged` |
|---|---|---|
| `predictions` | `NotifyPredictionsApplied` | **null** |
| `store_items` | `NotifyStoreApplied` | **null** |
| `store_profile_gifts` | **`NotifyStoreApplied` نفسها** | **null** |
| `store_products` | `NotifyStoreApplied` | `OnStoreProductsChanged` ← **الوحيد غير المعدوم في الاثني عشر** |

⇒ 🚩 **إشارة `changed` بلا حمولة لا تفعل شيئًا لأيّ مفتاح غير `store_products`**، و`onChanged == null`
يُسجَّل `LogUnsupported("changed")` (`0x328B9C0` → `0x52465BC`).
و⭐ `stamp` في `OnContentChangedReceived` @`0x5246910` **لا يُستعمل إطلاقًا**.

**المشتركون** (مسح `bl`+`b` على `add_`/`remove_`، ١٣ موضعًا):
`OnStoreApplied` ← `Store.Awake` (**بلا إلغاء اشتراك**) · `MiniStore` · `StoreCoinsSection` · `Subscription`.
`OnUpcomingPredictionsApplied` ← `MenuWinSection` وحده.

## ٧. ما لم يُحسَم 🟡

1. **أسماء حقول الظرف نصًّا على السلك**: الإزاحات والترتيب ✅، لكن لا `[JsonProperty]` ولا أثر
   للأسماء في `ScriptString` (و`DeserializeObject` بـ`settings = 0`) ⇒ **لا تُحسَم من الثنائي**.
   والخطر العمليّ معدوم: Newtonsoft غير حسّاس لحالة الأحرف.
2. **دلالة `Cursor` عند الخادم** (تسلسل أم طابع زمنيّ) — العميل يخزّنه ويعيد إرساله فقط. 🔒
3. `b__34_7`/`_11`/`_19` (`mass_events` · `achievements` · `app_announcements`) — فُكّ `b__34_15`
   وحده، والباقي بالحجم والبنية نفسها 🟡.
4. هل تسريب مشترك `Store` حقيقيّ (تابعٌ لدوام الكائن) 🟡.
5. تسمية عضوَي `Nullable<DateTime>` — الرايَة @`+0x28` والقيمة @`+0x30`، **خلاف الترتيب الشائع** 🟡.
6. الدالّة المُناداة على `ContentSyncService` داخل `OnStoreProductsChanged` 🟡.
