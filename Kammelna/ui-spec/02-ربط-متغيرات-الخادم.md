# ٠٢ — طبقة ربط متغيّرات الخادم

[↩ الفهرس](README.md)

> **١٩٣ موضع استدعاء** عبر التطبيق ✅ — هذه هي الآليّة التي تجعل الواجهة تتفاعل تلقائيًّا مع
> تغيّر حالة الخادم. أشرتُ إليها في [`sound-spec`](../sound-spec/README.md) و[`replay-spec`](../replay-spec/README.md)
> دون توثيق؛ هذا الفصل يسدّ ذلك.

## ⭐ الفكرة في سطر

بدل أن تستطلع الواجهة الخادم، **تُسجّل `Action` على اسم متغيّر SFS معيّن**، فتُستدعى تلقائيًّا
كلّما غيّر الخادم ذلك المتغيّر — والربط **مقرون بعمر `GameObject`** فيُنظَّف من نفسه.

```csharp
// مثال حقيقيّ من GameSoundManager (sound-spec §٢)
VariableBinderExtensions.Bind(gameObject, _game.Room, "pv", new Action(OnVoiceActorsChanged));
// ⇒ أي تغيّر في متغيّر الغرفة "pv" يعيد توزيع أصوات اللاعبين فورًا
```

---

## ١. البنية ✅

```csharp
public class BindAction {                 // TypeDefIndex 3889
    GameObject GameObject;  // 0x10   ← مِلك العمر
    Action     Action;      // 0x18   ← ما يُنفَّذ
    object     Owner;       // 0x20   ← اختياريّ
}

public class VariableBinder {             // TypeDefIndex 3888
    IDictionary<string, IDictionary<string, List<BindAction>>> binds;   // 0x10
    //           ↑ bindId              ↑ اسم المتغيّر
}
```

> ⭐ **قاموس ذو مستويين**: `bindId` → اسم المتغيّر → قائمة الأفعال.
> ⇒ عدّة مكوّنات تستطيع الاشتراك في نفس المتغيّر، ولا يعرف بعضها بعضًا.

### مفتاح الربط — `GetBindID` ✅ (فكّكتُهما بنفسي)
| الحمل | العنوان | الناتج |
|---|---|---|
| `GetBindID(User user)` | `0x52695BC` | **`"u" + user.Id`** |
| `GetBindID(Room room)` | `0x526969C` | **`"r" + room.Id`** |

> ⭐ **فضاء أسماء واحد للمستخدمين والغرف** يُفصَل ببادئة حرف واحد. بسيط ويعمل.

### الاشتراك في الخادم — `..ctor` @`0x526977C` ✅
```csharp
binds = new Dictionary<string, IDictionary<string, List<BindAction>>>();
SFS.OnUserVariableUpdate += OnUserVariableUpdate;      // Action<User, List<string>>
SFS.OnRoomVariableUpdate += OnRoomVariableUpdate;      // Action<Room, List<string>>
```
> ⭐ **نقطتا دخول اثنتان فقط في التطبيق كلّه.** كل التفاعليّة تمرّ منهما.

---

## ٢. الواجهة العامّة — خمسة أحمال ✅

```csharp
public static class VariableBinderExtensions {
    void Bind(GameObject go,      User user, string varName, Action action, object owner);
    void Bind(GameObject go,      Room room, string varName, Action action);
    void Bind(TextMeshProUGUI tm, User user, string varName, string defaultValue);
    void Bind(TextMeshProUGUI tm, Room room, string varName, string defaultValue);
    void Bind(RankSetter rankSetter, User user);
    void Unbind(GameObject go);
}
```

### ⭐ الاستعمال الفعليّ — عددتُ المستدعين بنفسي ✅

| الحمل | العنوان | المستدعون |
|---|---|---|
| `Bind(GameObject, Room, …)` | `0x526C360` | **٨٨** |
| `Bind(GameObject, User, …)` | `0x526C250` | **٤٩** |
| `Unbind(GameObject)` | `0x526C7F0` | **٤٤** |
| `Bind(TMP, Room, …)` | `0x526C598` | ٧ |
| `Bind(TMP, User, …)` | `0x526C460` | ٥ |
| **`Bind(RankSetter, User)`** | `0x526C6CC` | **٠ — كود ميّت** 🛑 |
| | | **المجموع ١٩٣** |

> ⭐ **حملا `TextMeshProUGUI` ربط تصريحيّ بلا كود**: تُمرّر نصًّا افتراضيًّا، ويتكفّل الغلاف
> بتحديث `tm.text` من قيمة المتغيّر. اثنا عشر موضعًا فقط — لكنّها أنظف نمط في النظام.
>
> ⚠️ **`Bind(RankSetter, User)` بلا مستدعين** — حمل مُعدّ ولم يُستعمل.
>
> 🛑 **٨٨ + ٤٩ = ١٣٧ ربطًا مقابل ٤٤ فكًّا فقط.** الفارق ليس تسرّبًا — انظر §٤.

## ٣. مسار التوزيع ✅

```
SFS.OnRoomVariableUpdate(room, changedVars)
   └─ OnRoomVariableUpdate @0x5269918   (48B — غلاف)
        └─ GetBindID(room) ⇒ "r{id}"
             └─ DispatchRoomUpdate ⇒ DispatchUpdate(bindId, changedVars) @0x526A5B0
                  ├─ ClearNulls()                                  ⭐ أوّلًا دائمًا
                  ├─ لكل varName في changedVars:
                  │     binds[bindId][varName] ⇒ List<BindAction>
                  └─ SafelyDispatchBindActions(list)
```

### ⭐⭐ `SafelyDispatchBindActions` @`0x526B3D0` (544B) ✅
```csharp
foreach (var ba in bindActions) {
    try   { ba.Action(); }
    catch (Exception e) { Debug.LogException(e); }     // ← @0x67EEAB4
}
```
> ⭐ **كل فعل معزول في `try/catch`**: استثناء في مشترك واحد **لا يمنع بقيّة المشتركين**.
> هذه أهمّ سطر في النظام كلّه — **انسخه**. بدونه يكفي عطب واحد لتجميد الواجهة كلّها.

### `DispatchAllBoundedVars` @`0x526B5F0` (1,064B) ✅
يُطلق **كل** الأفعال المرتبطة بمعرّف معيّن دفعةً واحدة (لا متغيّرًا بعينه)
— يُستعمل عند دخول كائن جديد ليُهيَّأ من الصفر. ويستدعي `ClearNulls` أوّلًا هو الآخر ✅.

## ٤. ⭐ إدارة العمر — `ClearNulls` @`0x526AA78` (2,392B)

**تُستدعى من `DispatchUpdate` و`DispatchAllBoundedVars` كليهما** ✅ (تحقّقت: `bl #0x526AA78`
عند `0x526A648` و`0x526B66C`).

> ⭐⭐ **التنظيف كسول لا استباقيّ**: عندما يُدمَّر `GameObject` **لا يُفكّ ربطه فورًا**؛
> بل يبقى في القاموس حتى أوّل توزيع تالٍ، فتزيله `ClearNulls`.
>
> ⇒ **هذا يفسّر الفارق ١٣٧ ربطًا مقابل ٤٤ فكًّا**: أغلب المكوّنات **لا تفكّ ربطها إطلاقًا**
> وتعتمد على التنظيف الكسول. تصميم مقصود لا إهمال.
>
> ⚠️ **المقابل**: بين تدمير الكائن وأوّل توزيع، يبقى `BindAction` حيًّا ممسكًا بمرجع
> `GameObject` مُدمَّر — أي أن **حجم القاموس يتضخّم في المشاهد قليلة التحديث**.
> في نسختك: نظّف عند `OnDestroy` أو اجعل المرجع ضعيفًا.

أربع لامدات (`<ClearNulls>b__15_0..3` @`0x526BEC4` · `0x526BE54` · `0x526BFF8` · `0x526C038`)
⇒ 🟡 على الأرجح: مسند التصفية، ومحدّد المفتاح، ومسندان للتنظيف على مستويَي القاموس.

---

## ٥. ⭐ `ReWire` — إعادة التوصيل عند تبديل الكائن

| الحمل | العنوان | الحجم |
|---|---|---|
| `ReWire(User newUser, User oldUser)` | `0x526BA18` | 68B |
| `ReWire(Room newRoom, Room oldRoom)` | `0x526BDA4` | 68B |
| `ReWire(string newID, string oldID)` | `0x526BA5C` | **840B** |

ينقل كل الارتباطات من معرّف قديم إلى جديد.
> ⭐ **الحاجة**: عند إعادة الاتّصال أو تبديل المقعد يُنشئ SmartFox كائن `User`/`Room` **جديدًا
> بمعرّف جديد**، فتصبح كل الارتباطات يتيمة. `ReWire` ينقلها بدل إعادة بنائها.
> **نقطة يسهل نسيانها في إعادة البناء** — وبدونها تتوقّف الواجهة عن التحديث بعد إعادة اتّصال.

## ٦. المنسّق — `CoordinatorVariableBinder`

نظام **ثانٍ موازٍ** بنفس البنية تقريبًا، لنطاق المنسّق (Coordinator) لا الغرفة:

| العضو | العنوان | الحجم |
|---|---|---|
| `Bind` / `BindInternal` | `0x5251830` / `0x5251968` | 312B / 1,096B |
| `Unbind` | `0x5251DB0` | 1,552B |
| `DispatchUpdate` | `0x525166C` | 452B |
| `DispatchAllForScope` | `0x52527F0` | 964B |
| `GetCurrent` | `0x52523C8` | 280B |
| `ClearCached` | `0x52524E0` | 776B |
| `ClearNulls` | `0x5252D38` | **2,392B — نفس حجم نظيره بالضبط** |
| `ReWire` | `0x5252BB4` | 380B |
| `SafelyDispatchBindActions` | `0x5253690` | 544B — **نفس الحجم** |

> ⭐ **`ClearNulls` و`SafelyDispatchBindActions` متطابقان في الحجم بايتًا ببايت** مع نظيريهما
> في `VariableBinder` ⇒ **نسخ ولصق** 🟡. في نسختك: **اجعلهما نوعًا معمَّمًا واحدًا**.
>
> ⭐ ما يميّز هذا النظام: **`GetCurrent`** (قراءة فوريّة للقيمة الحالية) و**`ClearCached`**
> — أي أنه يحتفظ بذاكرة مؤقّتة للقيم، بخلاف `VariableBinder` الذي يقرأ من كائن SFS مباشرةً.

## ٧. ⭐ قائمة إعادة البناء

1. **قاموس ذو مستويين** `bindId → varName → List<BindAction>`، والمعرّف `"u"/"r" + Id`.
2. **نقطتا دخول اثنتان فقط**: تحديث متغيّر مستخدم، وتحديث متغيّر غرفة.
3. **اعزل كل فعل في `try/catch`** — أهمّ سطر في النظام.
4. **اقرن الربط بعمر `GameObject`**، ونظّف — لكن **لا تعتمد على التنظيف الكسول وحده**.
5. **لا تنسَ `ReWire`** عند إعادة الاتّصال أو تبديل الكائن.
6. **وفّر حملًا تصريحيًّا لـ`Text`** بقيمة افتراضية — أنظف نمط في النظام.
7. **وحّد المنسّق والغرفة في نوع معمَّم واحد** — الأصل ينسخهما.
