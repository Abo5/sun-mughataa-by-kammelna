# ٠٥ — محرّك القوائم مفكوكًا: `UpdateItems` · `GetNewItem` · التدوير · التمرير

[↩ الفهرس](README.md)

> **الفصل ٠١ رسم الخريطة؛ هذا الفصل يفكّ المحرّك.** كل ما وُصف هناك بـ«الدور مستنتَج من الاسم»
> صار هنا مقروءًا من كود الآلة تعليمةً تعليمة: حلقة الإطار، نافذة الرؤية، بركة العناصر،
> التمرير الحلقيّ، التثبيت بثلاثة أنماط، ودلالة `topOffset` و`m_skipSize` و`_contentEndOffset`.
> وانكشف أنّ الإطار **ليس من تأليف اللعبة**، وأنّ ٩٠٪ من ٣٤٣ كيلوبايت **تكرار**، وأنّ
> `NestedListViewController` **ميت بالكامل**.


## ٣. ⭐ فيزياء التمرير — `ListViewControllerBase::ComputeConditions` @`0x5341EF0` (504B)

مفكوكة بالكامل ✅:

```csharp
protected virtual void ComputeConditions() {
    // نقطة البداية: حرف النافذة على محور Z (المسار الأصليّ ثلاثيّ الأبعاد)
    m_StartPosition = Vector3.forward * (m_Extents.z - m_ItemSize.z * 0.5f);   // 0x5341F44

    if (m_Scrolling) {                                     // 0x5341F64
        m_ScrollDelta = Mathf.Clamp((m_ScrollOffset - m_LastScrollOffset) / Time.deltaTime,
                                    -m_MaxMomentum, +m_MaxMomentum);           // 0x5341F90
        m_LastScrollOffset = m_ScrollOffset;
    } else {
        m_ScrollOffset += m_ScrollDelta * Time.deltaTime;                      // 0x5341FC0
        if (m_ScrollReturn < float.MaxValue || m_ScrollOffset > 0f)
            OnScrollEnded();                                                   // vslot 18 @0x5342024
        // تخميد الزخم نحو الصفر من الجهتين، وبلوغ الصفر يُطلق OnScrollEnded مرّة أخرى
        while (m_ScrollDelta > 0) { m_ScrollDelta -= m_ScrollDamping*Δt; if (<0) {=0; OnScrollEnded();} }
        while (m_ScrollDelta < 0) { m_ScrollDelta += m_ScrollDamping*Δt; if (>0) {=0; OnScrollEnded();} }
    }

    m_ScrollReturn = float.MaxValue;                                           // 0x5342074 — يُصفَّر كل إطار
    if (listHeight > 0f && listHeight <= -m_ScrollOffset)                      // vslot 5 @0x534207C
        m_ScrollReturn = 1e-6f - listHeight;                                   // 0x358637BD @0x53420C0

```

و`OnScrollEnded` @`0x534286C` (172B) هو من ينفّذ الارتداد:
```csharp
m_Scrolling = false;
if (m_ScrollOffset > 0f)            { StartSettling(); m_ScrollOffset = 0f; m_ScrollDelta = 0f; }
if (m_ScrollReturn < float.MaxValue){ StartSettling(); m_ScrollOffset = m_ScrollReturn; m_ScrollReturn = 0f; }
```

> ⭐⭐ **هذا هو الارتداد المطّاطيّ كلّه**: `m_ScrollReturn` **علمٌ يُحمَل إطارًا واحدًا**
> يقول «تجاوزتَ النهاية، هذه هي الإزاحة المسموحة». حدّ الأعلى صفر مباشرة،
> وحدّ الأسفل `1e-6f − listHeight`. لا منحنيات ولا ثوابت سحريّة — فقط قصّ + تسوية.
> و`1e-6f` هي الهامش الذي يمنع التساوي التامّ فيعاد الشدّ إلى ما لا نهاية.

### التسوية (Settling) ✅ — البند المفتوح ٣ في ٠١
```csharp
// @0x5342A30 (176B)

    m_Settling = true;                                  // strb #1 → [this+0x48]
    if (onComplete != null) settlingCompleted += onComplete;   // Delegate.Combine + CAS على [this+0x50]
}
// @0x5342AE0 (80B)
protected virtual void EndSettling() {
    var h = settlingCompleted;   // [this+0x50]
    m_Settling = false;          // sturb wzr,[x19,#-8]  ⇐ 0x50-8 = 0x48
    h?.Invoke();                 // ldr x9,[x8,#0x18] ; blr x9
    settlingCompleted = null;    // str xzr,[x19]
```

⇒ **التسوية ليست «تأجيل عمل ثقيل»** كما خُمِّن في ٠١ (🛑 تصحيح)، بل **حالةُ استقراء
(interpolation) للمواضع**: طالما `m_Settling` صحيح تُحرَّك العناصر بالـ`Lerp` نحو هدفها (§٩)،
وحين يبلغ الجميعُ هدفه يُنادى `EndSettling` فيُطفأ العلم وتُستدعى ردود النداء المنتظرة **مرّة واحدة**.

```csharp

protected virtual float ComputeListHeight() {
    if (m_Data == null) return 1f;
    float h = m_Data.Sum(d => TemplateSize(d.template))
            + m_Padding * Math.Max(m_Data.Count - 1, 0);                // bic w8,w8,w8,asr #31 = max(n-1,0)
```

> ⭐⭐⭐ **إذن**:
> * **`listHeight` = (طول المحتوى − طول النافذة)** مقصوصًا إلى ١ على الأقلّ = **مدى التمرير المسموح**.
>   وهو بالضبط ما يستعمله `ComputeConditions` الأساس لحدّ الأسفل. كلّ شيء متّسق.
> * **`m_skipSize` = طول المحتوى الكامل بحواشيه ناقصًا الصفّ المثبَّت** = **دورة الالتفاف**
>   في التمرير الحلقيّ (§٦). (لاحظ الفرق المقصود: `m_skipSize` يضرب الحاشية × `Count`،
>   و`ComputeListHeight` يضربها × `Count−1`.)
> * **`topOffset`** ليس حاشية تخطيط بل **الإزاحة الابتدائيّة للتمرير**: `Start` تضع
>   `m_ScrollOffset = topOffset` ثمّ تقيس القوالب.

```csharp
      acc += itemSize; laid++;
  }

  // ── ٣) خاتمة التثبيت (§٧) ─────────────────────────────
  //     … ثم:
  _contentEndOffset = m_ScrollOffset + acc + m_Padding * laid + inset;     // ⭐ 0x3FBF960
  if (doneSettling && m_Settling) EndSettling();                           // 0x3FBF984
}
```

> ⭐ `_contentEndOffset` **لا يُستعمل داخليًّا**؛ هو **مخرج للخارج**، يقرؤه:
> ```csharp
> // PositionAtContentEnd(RectTransform trailing, float gap) @0x3FBFA04 (244B)
> if (trailing != null)
>     trailing.localPosition = m_StartPosition + moveVector * (gap + _contentEndOffset);
> ```
> ⇒ **زرّ «تحميل المزيد» أو حاشية أسفل القائمة تُعلَّق على آخر صفّ فعليّ** دون أن تدخل
> دورة التدوير. تصميم أنيق: العنصر الذيليّ ليس صفًّا، بل `RectTransform` مستقلّ
> يُعاد وضعه كل إطار.

> ⚠️ **مصيدة `_exitingItems`**: أي صفّ له متتالية خروج جارية **يُتخطّى كليًّا** — لا يُحدَّث
> ولا يُعاد للبركة — لكن **`order` يزداد له**. ⇒ إن عَلِقت متتالية (استثناء داخل
> `OnComplete` مثلًا) بقي الصفّ محسوبًا في الترتيب إلى الأبد وظهرت فُرجة دائمة في القائمة 🚩.

## ٦. ⭐⭐ التمرير الحلقيّ مفكوكًا — بركتان لا واحدة

بعد رسم النسخة الأصليّة للصفّ، إن كان `loopScroll` مفعَّلًا:

```csharp

int loops = 1;                                       // w26
if (end + m_skipSize > 0f) {                         // 0x3FBF1D0
    int order2 = count + order;                      // ⭐ كل دورة تزيح الترتيب بعدد الصفوف
    while (offset + loops*m_skipSize < viewSize) {    // 0x3FBF1E8
        UpdateVisibleItem(datum, order2, inset + offset + loops*m_skipSize,
                          ref doneSettling, loops);   // vslot 37 (النسخة ذات الـ٥ وسائط)
        loops++;  order2 += count;
        if (!(end + loops*m_skipSize > 0f)) break;
    }
}
if (loops > maxLoopsReached) maxLoopsReached = loops;             // 0x3FBF258
for (int L = loops; L <= maxLoopsReached; L++) {                  // 0x3FBF2CC
    float d = L * m_skipSize;
    if (end + d >= 0f && offset + d <= viewSize) continue;        // ما زالت مرئيّة
    Recycle(new Tuple<int,int>(datum.index, L));                  // vslot 36
}
```

> ⭐⭐ **البركتان**: النسخة الأصليّة تُسجَّل في `m_ListItems` (`Dictionary<int,TItem>`، تخدمها
> `UpdateVisibleItem/4` فتحة ٢٧ و`GetNewItem/2` فتحة ٣٠ و`Recycle(int)` فتحة ٢٥)،
> ونُسخ الالتفاف في `m_ListLoopedItems` (`Dictionary<Tuple<int,int>,TItem>`، تخدمها
> `UpdateVisibleItem/5` فتحة ٣٧ و`GetNewItem/3` فتحة ٣٨ و`Recycle(Tuple)` فتحة ٣٦).
> **مفتاح `(الفهرس، رقم الدورة)`** — وهو ما ذكره الفصل ٠١ وقد تأكّد ✅.

> 🚩 **`maxLoopsReached` لا يُصفَّر أبدًا** (`str w26` تحت شرط `>` فقط، و`Awake`/`Start`/`set_data`
> لا تلمسه). ⇒ بعد جلسة تمرير طويلة يصير مسحُ التنظيف `O(count × maxLoopsReached)`
> **كل إطار** حتى لو رجعت القائمة إلى أوّلها. علّة أداء تراكميّة صريحة.

## ٧. ⭐⭐⭐ التثبيت: **ثلاثة** أنماط، والافتراضيّ ليس ما وصفه الفصل ٠١

🛑 **تصحيح للفصل ٠١**: قال ٠١ «العنصر المثبَّت يُستنسَخ … بينما **يبقى الأصل في مكانه داخل
القائمة**». هذا صحيح **لنمط واحد من ثلاثة**، وهو **ليس** الافتراضيّ. الافتراضيّات المقروءة
من الثنائي ✅:

| الخطّاف | العنوان (`<object,object>`) | الحجم | القيمة الافتراضيّة |
|---|---|---|---|
| `KeepPinnedDatumInList(pinned)` | `0x3FC1D70` | 8B | `mov w0,#0 ; ret` ⇒ **false** |
| `UsesClonedHeader(pinned)` | `0x3FC1D78` | 8B | `mov w0,#0 ; ret` ⇒ **false** |
| `OnPinnedCloneReady(clone,datum)` | `0x3FC1D80` | 4B | `ret` ⇒ لا شيء |
| `OnPinnedCloneShown(clone,datum)` | `0x3FC1D84` | 4B | `ret` ⇒ لا شيء |
| `ResolveCloneSource(datum,prefab)` | `0x3FC1D88` | 8B | `mov x0,x2 ; ret` ⇒ **نفس القالب** |

⚠️ لاحظ: `GetPinnedHeight` بحجم **٤ بايت** — `ret` وحدها. ليست كعب `NotImplementedException`
(ذاك ٦٤ بايتًا) بل **دالّة هويّة** تستفيد من كون الوسيط والقيمة المعادة في نفس السجلّ `s0`.

### الأنماط الثلاثة، كما تفرّعها خاتمة `UpdateItems`

```
        ┌ Keep=false, Cloned=false  (الافتراضيّ) ──────────────────────────────┐
        │  • الصفّ يُتخطّى في الحلقة الرئيسة (لا يُرسم في مساره)                │
        │  • خاتمة 0x3FBF41C→0x3FBF758:                                        │
        │      m_ListItems.TryGetValue(pinned.index, out existing)             │
        │      UpdateVisibleItem(pinned, count*maxLoops+count+order,           │

        │                                                     m_Size[DIM]);    │

        └──────────────────────────────────────────────────────────────────────┘
        ┌ Keep=false, Cloned=true ─────────────────────────────────────────────┐
        │  • Recycle(pinned.index) + Recycle(Tuple(index,L)) لكل L            │
```

> ⭐⭐ **رقم الترتيب `count*maxLoopsReached + count + order`**: أكبر من أي ترتيب يمكن أن
> يناله صفّ عاديّ أو نسخة التفاف. وبما أنّ `order` يُترجَم حرفيًّا إلى
> `Transform.SetSiblingIndex` (§٩) فإنّ **الرأس المثبَّت يُرسم فوق الجميع** بالضرورة
> الحسابيّة، لا بـ`Canvas` منفصل ولا بـ`sortingOrder`. حيلة نظيفة جدًّا.

> ⭐ والعنصر المثبَّت **حين يُنشأ لأوّل مرّة أثناء التسوية يُقفَز مباشرة** إلى موضعه
> (`item.localPosition = …` — فتحة الواجهة ٢ = `set_localPosition`) بدل أن يستقرئ من
> موضع العنصر السابق. بلا هذا السطر يُرى الرأس المثبَّت «يطير» من وسط القائمة إلى أعلاها.

### 🚩 علّة كامنة مؤكَّدة: إزاحة `AnimateScrollTo` مختلفة عن إزاحة التخطيط

`UpdateItems` تزيح **كل** الصفوف بـ`GetPinnedHeight + GetPinnedTopOffset + m_Padding`
**بلا شرط** (`0x3FBF53C`). أمّا حساب هدف التمرير فيستعمل صيغة أخرى:

```csharp
// PinnedScrollInset @0x3FC1390 (156B) — ونفس المنطق مضمَّن داخل AnimateScrollTo @0x3FC0FB8..0x3FC1018
```

> ١. **قيمة الإرجاع تعني «أُنشئ كائن جديد»، لا «نجحت العمليّة»**. `true` = دفعنا ثمن
>    `Instantiate`. (والمناداة الوحيدة لها تتجاهل القيمة، فهي عمليًّا مؤشّر تشخيصيّ.)
> ٢. **`item.Setup(datum, firstTime)`** — و`firstTime` هو **عكس** «جاء من البركة». هذا هو

> ٣. **`m_LastUpdatedItemItem`**: العنصر الجديد يُوضع أوّلًا في موضع **آخر عنصر حُدِّث**
>    لا في مركز الأب. ⇒ العنصر الداخل «ينزلق من عند جاره» بدل أن يطير من الأصل.
>    سطر واحد يفرق بين تمرير ناعم وتمرير يقفز.

```csharp
    if (!dontSettle && m_Settling && m_EnableSettling) {

            doneSettling = false;                                          // strb wzr,[x21]
```

## ١٤. خلاصة لإعادة البناء

| القرار | القيمة المقروءة من الثنائي | ⚠️ |
|---|---|---|
| مصدر الإطار | `ListViewFramework` من Unity Labs (VR) + محوِّل `UiListView` | لا تستورد بقيّة `rayOrigin`/`SetMaterialClip` |
| حلقة التشغيل | `Update → UpdateView → ComputeConditions + UpdateItems` | **أضف حراسة**: لا تعمل إن لم تتغيّر إزاحة ولا بيانات |
| نافذة الرؤية | `itemSize + offset ≥ inset` **و** `offset ≤ viewSize + itemSize` | هامش عنصر واحد على الحرف البعيد |
| إزاحة الصفّ | `m_ScrollOffset + Σالأحجام + m_Padding×n (+ inset)` | الأحجام من `m_TemplateSizes[template][DIM]` لا من قياس كل إطار |
| `topOffset` | **الإزاحة الابتدائيّة** لا حاشية | `m_ScrollOffset = topOffset` في `Start` |
| `listHeight` | `(طول المحتوى − طول النافذة)` مقصوصًا ≥ `1f` | = **مدى التمرير**، وهو ما يحدّ الارتداد |
| `m_skipSize` | طول المحتوى بحواشيه − الصفّ المثبَّت | **دورة الالتفاف** الحلقيّ |
| `_contentEndOffset` | إزاحة ما بعد آخر صفّ | مخرج لـ`PositionAtContentEnd` (حاشية/زرّ ذيليّ) |
| الارتداد | `m_ScrollReturn` علم إطار واحد + `1e-6f − listHeight` | يُصفَّر إلى `float.MaxValue` كل إطار |
| الزخم | `clamp((Δoffset)/Δt, ±m_MaxMomentum)` ثم تخميد بـ`m_ScrollDamping×Δt` | العبور إلى الصفر يُطلق `OnScrollEnded` |

| عقد الصفّ | `Setup(datum, firstTime)` حيث `firstTime = !جاء من البركة` | فرع `false` **يجب** أن ينظّف الحالة القديمة |
| موضع الميلاد | `item.localPosition = m_LastUpdatedItemItem.localPosition` | سطر واحد يمنع «طيران» العناصر الجديدة |
| ترتيب الرسم | `order → Transform.SetSiblingIndex(order)` | لا `sortingOrder` ولا `Canvas` فرعيّ |
| رأس مثبَّت فوق الجميع | `order = count×maxLoops + count + order` | ضمان حسابيّ لا بصريّ |
| أنماط التثبيت | ثلاثة: أصل-لاصق (افتراضيّ) · نسخة · أصل+نسخة | الافتراضيّ `Keep=false, Cloned=false` |
