## 1. نموذج الورقة (Card)

✅ `[CS: Card.cs]`

```csharp
public class Card {
    public Rank Rank { get; }   // readonly
    public Suit Suit { get; }   // readonly
    public Card(Rank rank, Suit suit);
    public int AsInt() => (int)Suit * 13 + (int)Rank;
}
```

الورقة **غير قابلة للتغيير** (immutable) وتتكوّن من حقلين فقط: `Rank` و`Suit`.

### 1.1 الأنواع (Suit)

✅ `[ENUM: Suit]` — `[CS: Suit.cs]`

| القيمة | الاسم البرمجي | الاسم العربي | الاسم العامي في اللعبة | اللون | الحرف في الترميز |
|---|---|---|---|---|---|
| 0 | `SPADES` | البستوني | **السبيت** / «الكالة» | أسود | `s` |
| 1 | `HEARTS` | الكبة | **الهاص** / «اللال» | أحمر | `h` |
| 2 | `CLUBS` | السباتي | **الشريّا** | أسود | `c` |
| 3 | `DIAMONDS` | الديناري | **الديمن** / «الشوكة» | أحمر | `d` |
| 4 | `NONE` | — | لا نوع (قيمة حارسة) | — | — |

> الأسماء العامية مأخوذة حرفيًا من شاشة التعليم داخل اللعبة ⚪ `[LOC: How_to_play_1]`:
> «ينقسم ورق اللعب إلى لونين: ١ الأحمر: الهاص "اللال"، الديمن "الشوكة". ٢ الأسود: السبيت "الكالة"، الشريّا.»
>
> أحرف الترميز `s/h/c/d` مؤكّدة من أسماء مقاطع الصوت المستخرجة (`s`, `h`, `c`, `d`, `spades`, `hearts`, `clubs`, `diamonds`) ✅.

### 1.2 المراتب (Rank)

✅ `[ENUM: Rank]` — `[CS: Rank.cs]`

| القيمة | الاسم البرمجي | الاسم العامي | تُستخدم في البلوت؟ |
|---|---|---|---|
| 0 | `TWO` | اثنين | ❌ |
| 1 | `THREE` | ثلاثة | ❌ |
| 2 | `FOUR` | أربعة | ❌ |
| 3 | `FIVE` | خمسة | ❌ |
| 4 | `SIX` | ستة | ❌ |
| 5 | `SEVEN` | **السبعة** | ✅ |
| 6 | `EIGHT` | **الثمانية** | ✅ |
| 7 | `NINE` | **التسعة** | ✅ |
| 8 | `TEN` | **العشرة** | ✅ |
| 9 | `JACK` | **الولد** | ✅ |
| 10 | `QUEEN` | **البنت** | ✅ |
| 11 | `KING` | **الشايب** | ✅ |
| 12 | `ACE` | **الإكة / البنط** | ✅ |
| 13 | `NONE` | — | قيمة حارسة |

> **مهم**: التعداد يحتوي المراتب من `TWO` إلى `ACE` لأن نفس النموذج يخدم الطرنيب والجاكارو (٥٢ ورقة).
> البلوت يستخدم **٣٢ ورقة فقط**: `SEVEN`(5) … `ACE`(12) × ٤ أنواع.
> ⚪ `[LOC: How_to_play_2]`: «عدد ورق اللعب ٣٢ ورقة مقسمة على ٨ من كل نوع.»

✅ مجموعة أوراق البلوت مُعرّفة في `[CS: BalootCardUtils.cs → BalootCardRanks / AllBalootCards]`
وهي حاصل الضرب الديكارتي لـ `BalootCardRanks × SuitMethods.GetAll()`.

## 2. الترميز (Serialization)

### 2.1 ترميز رقمي

✅ `[CS: Card.cs → AsInt]` و`[CS: CardUtils.cs → FromInt]`

```
cardInt = Suit * 13 + Rank          // 0..51
Suit    = cardInt / 13
Rank    = cardInt % 13
```

مثال: إكة السبيت = `0*13 + 12 = 12`. تسعة الهاص = `1*13 + 7 = 20`.

### 2.2 ترميز نصي

✅ `[CS: CardUtils.cs → FromString]`

```
string = <حرف النوع><رقم/رمز المرتبة>
FromString: suitPart = s.Substring(0,1) ; rankPart = s.Substring(1)
```

### 2.3 ترميز ثنائي مضغوط

✅ `[CS: CardUtils.cs → EncodeBinaryLongCards / DecodeBinaryLongCards]`
يُستخدم `long` كقناع بتات (bitmask) لليد كاملة — بت لكل ورقة حسب `AsInt()`.

### 2.4 دوال فك الترميز من الخادم

✅ `[CS: CardUtils.cs]`
- `DecodeCards(ISFSArray, index)` — يفك مصفوفة أوراق لاعب معيّن.
- `DecodeIntArrayCards(...)`
- `DecodeCardNumbers(...)`

## 3. قيمة الورقة بالأبناط (Points / أبناط)

هذه هي **النقاط التي تُجمع من الأكلات**.

✅ مقروءة حرفيًا من جدولين ثابتين في الثنائي عبر `[CS: KammelnaOffline.Baloot.BalootUtils.cs → GetCardValueForScores]`

### 3.1 جدول الصن (وكل ورقة غير حكم) — `[BIN: 0x7253488]`

| الورقة | الأبناط |
|---|---|
| الإكة (ACE) | **11** |
| العشرة (TEN) | **10** |
| الشايب (KING) | **4** |
| البنت (QUEEN) | **3** |
| الولد (JACK) | **2** |
| التسعة (NINE) | **0** |
| الثمانية (EIGHT) | **0** |
| السبعة (SEVEN) | **0** |

مجموع النوع الواحد = 11+10+4+3+2 = **30 بنط**. أربعة أنواع = **120**. + **10 أبناط لآخر أكلة** = **130 بنط** في الصن. ✅

> ⚪ `[LOC: ekka11] / [LOC: ashrra10] / [LOC: shayyb4] / [LOC: bent3] / [LOC: walaad2] / [LOC: 7 8 not calc]`
> تطابق الجدول الثنائي تمامًا (لاحظ: البنت = **٣** أبناط وليس ٤).

### 3.2 جدول الحكم — **لنوع الحكم فقط** — `[BIN: 0x725349C]`

| الورقة | الأبناط |
|---|---|
| الولد (JACK) | **20** |
| التسعة (NINE) | **14** |
| الإكة (ACE) | **11** |
| العشرة (TEN) | **10** |
| الشايب (KING) | **4** |
| البنت (QUEEN) | **3** |
| الثمانية (EIGHT) | **0** |
| السبعة (SEVEN) | **0** |

مجموع نوع الحكم = 20+14+11+10+4+3 = **62 بنط**.
الأنواع الثلاثة الأخرى تُحسب بجدول الصن = 30 × 3 = **90**.
المجموع 152 + **10 لآخر أكلة** = **162 بنط** في الحكم. ✅

> ⚪ `[LOC: walaad2]`: «الولد: بنطين. ويحتسب بـ٢٠ بنط في حال الحكم فقط، وتحديدًا للنوع الذي اختير كحكم.»
> ⚪ `[LOC: tessa14]`: «التسعة: ١٤ بنط في حال الحكم فقط، وتحديدًا للنوع الذي اختير كحكم.»

### 3.3 التوقيع البرمجي

```csharp
// [CS: KammelnaOffline.Baloot.BalootUtils.cs]
public static int GetCardValueForScores(Card card, BalootGame.BalootGameMode gameMode)
```
🟡 المُستدعي يمرّر `Hokom` **فقط عندما تكون الورقة من نوع الحكم**؛ وإلا يمرّر `Sun`.
هذا هو السلوك الوحيد المتوافق مع مجموع 162 بنط.

## 4. ترتيب قوة الورقة (من يأكل من)

هذا **منفصل تمامًا** عن الأبناط.

✅ `[CS: KammelnaOffline.Baloot.BalootUtils.cs → GetCardValueRank]`

### 4.1 ترتيب الصن (وكل نوع غير الحكم) — `[BIN: 0x7253448]`

| الورقة | رتبة القوة |
|---|---|
| الإكة | **8** ← الأقوى |
| العشرة | 7 |
| الشايب | 6 |
| البنت | 5 |
| الولد | 4 |
| التسعة | 3 |
| الثمانية | 2 |
| السبعة | **1** ← الأضعف |

⚪ `[LOC: Play_types_1_son_b]`: «اكه ١٠ شايب بنت ولد ٩ ٨ ٧».

### 4.2 ترتيب نوع الحكم — `[BIN: 0x7253468]`

| الورقة | رتبة القوة |
|---|---|
| الولد | **16** ← الأقوى |
| التسعة | 15 |
| الإكة | 14 |
| العشرة | 13 |
| الشايب | 12 |
| البنت | 11 |
| الثمانية | 10 |
| السبعة | **9** |

⚪ `[LOC: Play_types_1_kukum_b]`: «ولد ٩ اكه ١٠ شايب بنت ٨ ٧».
⚪ `[LOC: Play_types_1_hukum_a]`: «الحكم: ينتقل (الولد والـ٩) في المقدمة لنفس نوع الحكم فقط!»

> ✅ **ملاحظة تصميمية مهمة**: قيم الحكم (9..16) أعلى دائمًا من قيم الصن (1..8).
> بهذا تكفي مقارنة عددية واحدة ليفوز أي ورقة حكم على أي ورقة غير حكم.
> **كرّر هذا التصميم بالضبط في نسختك.**

### 4.3 دالة القيمة الثانية (المستخدمة داخل لعبة الواجهة)

✅ `[CS: BalootCardUtils.cs → GetValue(Card)]` — تُنتج قيمة مركّبة للفرز والمقارنة السريعة:

```
base = ترتيب أساسي:  SEVEN=1, EIGHT=2, NINE=3, JACK=4, QUEEN=5, KING=6, TEN=7, ACE=8
                     [BIN: 0x72536C0] يحتوي TEN..ACE = [7, 4, 5, 6, 8]

if (GameMode == Sun || Ashkal):
     value = (card.Suit == CurrentSuit) ? base * 100 : base

if (GameMode == Hokom):
     if (card.Suit == TrumpSuit):
            JACK  → 10000
            NINE  →  9000
            else  → base * 1000
     else:
            value = (card.Suit == CurrentSuit) ? base * 100 : base
```

**المعنى**: الورقة التي لا تتبع النوع المطلوب ولا هي حكم تحصل على قيمة صغيرة جدًا (1..8)
فلا تفوز أبدًا باللفة. ✅

## 5. ترتيب الأوراق في اليد (الفرز البصري)

✅ `[CS: CardUtils.cs → SortCards / GetSuitOrder / SuitComparison / ValueComparison]`

1. `GetSuitOrder(cards)` تحسب ترتيب الأنواع الموجودة فعليًا في اليد بحيث **تتبادل الألوان**
   (لا يجاور نوع أسود نوعًا أسود) — لتسهيل القراءة البصرية.
2. `SuitComparison` تفرز حسب موضع النوع في ذلك الترتيب.
3. `ValueComparison` تفرز داخل النوع حسب `GetValue`.
4. `OriginalCardOrder` (للترتيب الخام) تقارن بـ `AsInt()`.
