```
┌─ START_ROUND  [SFS: "sr"]
│
│  ① التوزيع الأول: 3 أوراق ثم 2 أوراق لكل لاعب (عكس عقارب الساعة)   ⚪ [LOC: How_to_play_3]
│  ② الموزّع يضع ورقة مكشوفة في الميدان ويقول «أوّل»                  [SFS: "fc"] FLOOR_CARD
│                                                                       صوت: awal
│  ③ Stage = Bidding
│     └── جولة «أوّل»  : كل لاعب: حكم / صن / أشكل / بس
│     └── جولة «ثاني»  : ولا / صن / يقلب صن / قبلك صن / حكم٢ / ورق
│     └── تحديد نوع الحكم (سبيت/هاص/شريا/ديمن) + مفتوح أو مقفل
│     └── جولة التدبيل : دبل / ثري / فور / قهوة
│  ④ اكتمال التوزيع: 3 أوراق لكل لاعب،
│     والمشتري يأخذ ورقتين + ورقة الميدان.                             ⚪ [LOC: How_to_play_3 §5]
│     النتيجة: 8 أوراق لكل لاعب.
│  ⑤ إعلان المشاريع (في اللفة الأولى فقط)                             [SFS: "dp"], [SFS: "prcs"]
│
│  ⑥ Stage = Playing — تكرار 8 مرات:
│        ├ اللاعب صاحب الدور يلعب ورقة        [SFS: "card"]
│        ├ الخادم يرسل PlayableCards          [SFS: "ppcs"] لكل لاعب في دوره
│        ├ بعد 4 أوراق → Stage = WaitingForEating
│        ├ حساب من أكل                        [CS: BalootUtils.CheckWhoEats]
│        └ أنيميشن الأكلة → الآكل يبدأ اللفة التالية
│
│  ⑦ اللفة الثامنة: +10 أبناط «آخر أكلة»
│  ⑧ (اختياري) مرحلة التقييد Stage = InCheatCatch   [SFS: "chup"], [SFS: "live_catch"]
│
└─ END_ROUND [SFS: "er"] → النشرة (BalootRoundBoardPopup) → جولة جديدة أو…
   END_GAME  [SFS: "eg"] عند وصول فريق إلى 152 نقطة
```

## ٦ب. ⭐⭐⭐ دورة حياة الجولة والمباراة في الأوفلاين — مفكوكة بالكامل ✅

> المحرّك الأوفلاين هو **التنفيذ المرجعيّ لقوانين بلوت** داخل التطبيق.
> هذا القسم يُكمل [٠٣ §٧](03-التوزيع-والمزايدة.md) ويغلق أوضح فجوة كانت في الأرشيف.

### ⭐⭐ الجواب على «أين تُصفَّر حقول الجولة؟» — **لا تُصفَّر إطلاقًا**

مسحٌ شامل لكل `str/strb/strh` على الإزاحات `0x98 · 0xA8 · 0xAC · 0xB0 · 0xB4 · 0xB5 · 0xB6 · 0xB8 · 0xBC`
عبر كل دوالّ `KammelnaOffline.*` (١٥٠٣ دالّة) ⇒ مواضع الكتابة **الوحيدة**:

| الحقل | الإزاحة | موضع الكتابة الوحيد | متى |
|---|---|---|---|
| `CurrentSuit` | `0x98` | `CheckEkkah` @`0x5204AC4` | **أوّل ورقة في كل طرحة** |
| `BestProjectTeam` | `0xA8` | `OnPlayCard` @`0x5202EAC` · `0x52034A4` | الحركة الأولى |
| `GameMode` | `0xAC` | `OnEndBidding` @`0x5201130` · `OnBid` @`0x520634C` | نهاية المزايدة |
| `ExtraGameMode` | `0xB0` | `OnEndBidding` @`0x5201198` · `OnBid` @`0x5206378` | نهاية المزايدة |
| `IsHokomClose` | `0xB4` | `OnEndBidding` @`0x520115C` | نهاية المزايدة |

| `LastMoveWinner` | `0xBC` | `OnEatCard` @`0x52053FC` · `0x520541C` | بعد كل أكلة |

| `EkkahProjectShown` | `0xB6` | `CheckEkkah` @`0x5204DE4` — **القيمة `1` فقط** | مرّة واحدة |

> ⭐ **التصفير بنيويّ لا صريح**: كل حقل **يُسنَد إسنادًا غير مشروط قبل أوّل قراءة له**،
> والقيم الابتدائية تأتي من **إنشاء كائن جديد**:
> `SFS.SwitchToOffline()` → `new OfflineSmartFoxClient()` → `GetGameController(0)` → `new BalootGameController()`
> — وهذه تُستدعى **مرّة واحدة في الثنائي كلّه**.
> و`OfflineGameController..ctor` @`0x51EEE9C` لا يفعل شيئًا سوى `PlayedCards = new Card[4]`.

> 🛑 **نتيجة سلوكية مهمّة**: `BalootProjectShown` و`EkkahProjectShown` **لا تعودان إلى `false` أبدًا**
> داخل جلسة أوفلاين واحدة. وهما تُقرآن في `OnPlayCard` @`0x5202B60`/`0x5202B68` كبوّابة تخطٍّ
> ⇒ **إعلان «بلوت»/«إكّة» يُعرض مرّة واحدة لكل جلسة، لا مرّة لكل جولة.**
> *(تحقّقت: مسحي وجد أربعة مواضع، لكن اثنين منها كتابة على كائن آخر (`BalootUtils.<>c`) ضمن
> تهيئة صنف il2cpp — تصادف إزاحة لا كتابة على المتحكّم.)*
