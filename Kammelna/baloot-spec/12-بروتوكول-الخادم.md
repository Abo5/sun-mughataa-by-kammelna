# ١٢ — بروتوكول الخادم (SmartFoxServer 2X)

[↩ العودة للفهرس](README.md)

> كل المفاتيح أدناه مقروءة حرفيًا من ثوابت `const string` في الكود المفكوك ✅.

## 9. ملاحظة معمارية لإعادة البناء

> اللعبة تتبع نمط **Authoritative Server** الكامل:
> - العميل **لا يحسب** الأوراق المسموحة ولا النقاط ولا الفائز في الوضع الأونلاين.
> - العميل يرسل **نيّة** (لعب ورقة/مزايدة/تقييد) ويستقبل **حالة** كاملة.
> - كل منطق اللعبة موجود أيضًا في العميل (`KammelnaOffline.Baloot`) لوضع الأوفلاين والتعليم.
>
> **للنسخة الجديدة**: ابنِ منطق القوانين مرة واحدة (كما في `BalootUtils`)
> واستعمله في الخادم وفي وضع الأوفلاين معًا.

## 10. ⭐ مفاتيح المزايدة عميل ← خادم (مُثبَتة من ARM64)

المصدر: `BalootBiddingButtons.SubmitBid` @`0x4F82AB8` — انظر
[١٥ §٣١.٢](15-تدقيق-ARM64.md). يُبنى `SFSObject` بمفتاح واحد قيمته `bool true`،
ويُرسَل عبر `game.SendBidding(sfs)`.

| الزر | المفتاح المُرسَل | القيمة |
|---|---|---|
| صن | `sun` | `true` |
| **على الصن** | `sun` | `true` |
| **قبل على الصن** | `sun` | `true` |
| حكم | `hokom` | `true` |
| **حكم ٢** | `hokom` | `true` |
| حكم + سباتي | `hokom` + `suit` | `true` + `"c"` |
| حكم + ديناري | `hokom` + `suit` | `true` + `"d"` |
| حكم + بستوني | `hokom` + `suit` | `true` + `"s"` |
| حكم + كبة | `hokom` + `suit` | `true` + `"h"` |
| أشكل | `ashkal` | `true` |
| دبل | `double` | `true` |
| تلت | `triple` | `true` |
| أربعة | `four` | `true` |
| قهوة | `qahwa` | `true` |
| حكم مفتوح | **`h_o`** | `true` |
| حكم مغلق | **`h_c`** | `true` |
| باس | `pass` | `true` |
| **ولا** | `pass` | `true` |
| **تأكيد الحكم** | `pass` | `true` |

> ⭐⭐ **قاعدة تصميم جوهرية للخادم**: العميل **لا يميّز** بين «صن / على الصن / قبل على الصن»،
> ولا بين «حكم / حكم ٢»، ولا بين «باس / ولا / تأكيد الحكم». كلها مفاتيح مشتركة.
> **التمييز يتمّ عند الخادم من حالة المزايدة (`BiddingState`) لا من المفتاح المُرسَل.**
>
> لمن يبني الخادم: لا تعتمد على اسم الزر إطلاقًا — اقرأ `state` وطبّق جدول الـ54 حالة
> ([`refs/bidding-states-53.md`](refs/bidding-states-53.md)).

### 10.1 الاتجاه المعاكس (خادم ← عميل)

في `LastAction.BidType` تصل الأسماء **الطويلة** لا المختصرة:

| عميل ← خادم | خادم ← عميل |
|---|---|
| `h_o` | `hokomopen` |
| `h_c` | `hokomclose` |
| `pass` | `pass` · `thany` · `waraq` · `wala` (مطبَّعة في `GetNextBidding`) |
| `sun` | `sun` · `turntosun` · `beforeyou` (مطبَّعة) |

> 🟡 هذه مطابقة **استنتاجية**: الطرفان مُثبَتان من الكود، لكن لم يُرصد موضع واحد
> يترجم بينهما صراحةً — الترجمة تتمّ على الخادم.

### 10.2 مفاتيح تُكتب مع كل ورقة تُلعب ✅

من `BalootGameController.CheckEkkah` @`0x5204A5C` — انظر [١٥ §٢٩.١](15-تدقيق-ARM64.md):

| المفتاح | النوع | المحتوى |
|---|---|---|
| `current_suit` | int | نوع الأرض بعد لعب الورقة |
| `ppcs` | int[] | **possible play cards** — الأوراق القابلة للعب، مُرمَّزة `Suit*13 + Rank` |

> ⭐ تُحدَّث **مع كل ورقة**، لا مرة واحدة في بداية الدور.

### 11.4 🛑 تصحيح: مفردات `gem` **حروف مفردة**

```csharp
// BalootGame.ExtraGameModeFromString @0x52FB0EC ✅
"d" → Double   "t" → Triple   "f" → Four   "q" → Qahwa   غير ذلك → NotDetermined
// BalootGame.GameModeFromString @0x52FB00C ✅
"sun" → Sun    "hokom" → Hokom    "ashkal" → Ashkal    غير ذلك → NotDetermined
```

> ⚠️ السلاسل `double` · `triple` · `four` · `qahwa` هي **سمات `[FriendlyName]` للعرض فقط**،
> وليست مفردات السلك. مؤكَّد بالاتجاهين: `ToClientString` @`0x52FBC44` تُنتج `d/t/f/q`.

### 11.7 ⭐⭐ تدوير المقاعد — قاعدة أساسية ✅

```csharp
// CardGame.SeatPlayer @0x5300DAC
MySeatIndex = seatIndex;
for (int k = 0; k <= 3; k++)
    Players[IsSpectator ? k : ((5 + k) - MySeatIndex) % 4].Index = k + 1;
```

> ⭐⭐ **`KPlayer.Index` = رقم المقعد المطلق عند الخادم (1..4)** ويُقارَن مباشرةً بـ
> `dealer` و`rb` و`rd`. أما **موضع العنصر داخل `players[]` فهو ترتيب العرض**، و`players[0]`
> هو **أنا** دائمًا. للمتفرّج لا تدوير.

### 11.8 آلة الحالة ✅

```csharp
enum CardGameStages { None=0, Bidding=1, Playing=2, WaitingForEating=3, InCheatCatch=4, MoveNextRequired=5 }
```
> ⭐ **لا يوجد جدول انتقالات في العميل.** يقرأ `gStg` ويُطلق `OnStageChanged` عند التغيّر.
> **كل منطق التحوّل على الخادم** — وهذا ما يجب أن تبنيه.
