# ١٢ — منسّق أنيميشن الورق: مخزن الأفعال والقيم المساعِدة

[↩ الفهرس](README.md)

> `CardGameVisualControls` هو **الأساس المشترك** لأنيميشن كل ألعاب الورق في «كملنا»
> (بلوت · طرنيب · جكارو). وثّق [أرشيف البلوت §٢](../baloot-spec/08-الأنيميشن-الكامل.md)
> نظرته العُليا (التمايل، الطابور، `CardAction`) بمستوى شبه-مُفكَّك. هذا الفصل يُكمِل
> **بقيّة الأساس بمستوى ARM64 بايتًا ببايت**: مُغلِّفات إضافة الأفعال للطابور، ودالّة
> موضع هبوط الورقة، وفهرس خانة اللاعب (**الذي تُعيد جكارو تعريفه**)، وقيم التمايل،
> وحدث `OnStageChanged`. الصنف الجكاروي المشتق: `JackarooCardGameVisualControls`
> (`0x51DB…`، `TypeDefIndex 3598`) — لذا مكان هذا الفصل هنا مُبرَّر: **`GetPlayerSlotIndex`
> يُلغى في جكارو ليعطي سلوكًا مختلفًا جوهريًّا** (خانة = فهرس ورقة متسلسل لا مقعد لاعب).

**سُلّم اليقين**: ✅ مُثبت من كود الآلة (ARM64) · 🟡 استنتاج · ⚪ نص داخل التطبيق

## ١. ⭐ مخزن الأفعال (Actions Buffer) — مُغلِّفات الإضافة

الطابور نفسه (`_actionsBuffer : List<CardAction> @0xF0`) وحقول التوقيت
(`_updateBufferTime@0x138`, `_pauseUntil@0x13C`, `_lastActionPlayedTime@0x140`,
`_isLastActionInBufferPlayCard@0x144`) موصوفة في
[البلوت §٢٫٤](../baloot-spec/08-الأنيميشن-الكامل.md). هنا **المُغلِّفات الثلاث**
التي تصفّ فعلًا جديدًا. الثلاثة **بنية واحدة**:

```
① حارس تهيئة صنف CardAction (ldrb/tbnz على 0x91E8xxx ثم il2cpp_runtime_class_init)
② x19 = this._actionsBuffer            ← ldr x19, [this, #0xF0]
③ action = CardAction.Init…(الوسائط)  ← bl إلى المُنشئ الجاهز
④ List<CardAction>.Add(_actionsBuffer, action)   ← موسَّعة سطريًّا (inlined):
       version++      ([x19,#0x1C] += 1)
       count  = [x19,#0x18] ; items = [x19,#0x10] ; cap = [items,#0x18]
       إن count < cap:  items[count] = action (offset 0x20 + count*8) ; count++
       وإلا:            AddWithResize(...)  @0x3464528
```

| الدالّة | العنوان | التوقيع (من `dump.cs`) | المُنشئ المُستدعى |
|---|---|---|---|
| `AddPlayedCardToActionsBuffer` | `0x53053B4` | `(Card, CardGamePlayer, Transform startingPoint, bool isEventFromServer, bool withCollision, int? gameActionId, int floorLayer, bool hideStartingPoint)` | ✅ `InitCardPlay` `0x53054DC` |
| `AddEatingToActionsBuffer` | `0x5305604` | `(CardGamePlayer, Transform eatingPoint, Sprite cardback, bool isLastEating)` | ✅ `InitEating` `0x53056E8` |
| `AddReorganizeHandToActionsBuffer` | `0x53057EC` | `(List<Card> allCards, List<Card> playableCards)` | ✅ `InitReorganizeHand` `0x53058B4` |

**المُستدعون** (مسح مراجع مُحقَّق):

| المُغلِّف | يُستدعى من |
|---|---|
| `AddPlayedCardToActionsBuffer` | ✅ `CardGameVisualControls$$PlayCard` (`bl` في `0x5305C50`) |
| `AddEatingToActionsBuffer` | ✅ `CardGameVisualControls$$EatCards` (`bl` في `0x5304AF4`) |
| `AddReorganizeHandToActionsBuffer` | 🚩 **لا مُستدعي** — انظر §٢ |

> `CardAction` وحقوله (`card@0x10 … playableCard@0x60`) و`isCardPlay/isEating/isReorganizeHand`
> مُوثَّقة في البلوت؛ لا أُكرِّرها. **الدلالة**: كل حركة (لعب/أكل/ترتيب) تتحوّل إلى كائن
> `CardAction` واحد يُدفَع في طابور واحد بمؤقّت، فلا تتداخل الحركات مهما تسارعت رسائل الخادم.

## ٢. 🚩 سلسلة «إعادة ترتيب اليد» ميتة في هذا البناء

مسحٌ شامل لتعليمات `bl` عبر النطاق `0x800000..0x7000000` أعطى **صفر مراجع** لكلٍّ من:

| الرمز | العنوان | مراجع `bl` |
|---|---|---|
| `AddReorganizeHandToActionsBuffer` | `0x53057EC` | **٠** |
| `InitReorganizeHand` (المُنشئ) | `0x53058B4` | **٠** |
| `get_isReorganizeHand` (المُستهلِك) | `0x5304B70` | **٠** |

`AddReorganizeHandToActionsBuffer` دالّة **نسخة (instance) عامّة غير ظاهريّة** (لا خانة vtable).
غياب أي `bl` إليها ⇒ لا تُستدعى مباشرة، والمُنشئ الوحيد الذي كانت ستستعمله (`InitReorganizeHand`)
والمُستهلِك الوحيد لفرعها (`isReorganizeHand`) **كلاهما بلا مراجع أيضًا**. ثلاثتها معًا سلسلة
مكتملة الانقطاع.

> ⚠️ **حدود اليقين**: قاعدة «صفر مراجع = موت» تُثبِت الموت قطعًا **للساكنة غير الظاهريّة**؛
> هذه نسخيّة، فيبقى احتمال نظريّ لاستدعائها عبر مفوّض/انعكاس. لا دليل على ذلك، ولا تُسنَد
> إلى `UnityEvent` (ليست معالِج زر). **الأرجح ⇐ ميزة مُبقّاة (vestigial)**: نوع الفعل الثالث
> موجود في `CardAction` لكن مسار «إعادة ترتيب اليد» غير مُفعَّل في هذا الإصدار. 🟡

## ٣. `GetCardLandingWorldPosition(KPlayer player) → Vector3` — `0x5306C28` ✅

يحسب **الموضع العالميّ** الذي تهبط عنده الورقة الملعوبة. أربعة نداءات ظاهريّة ثم تحويل نقطة:

```csharp
Vector3 GetCardLandingWorldPosition(KPlayer player) {
    SpriteRenderer sprite   = GetCardSprite(player);              // خانة 20 @vtbl 0x278
    Vector3 originalPos      = GetCardRestingLocalPosition(player);// خانة 17 @vtbl 0x248 → s0,s1,s2
    int slot                 = GetPlayerSlotIndex(player);        // خانة 18 @vtbl 0x258
    Vector3 originalRot      = _originalEatingCardsTransformsRotations[slot]; // مصفوفة @0xC8، عنصر 12B
    AdjustOpponentCardStart(ref originalPos, ref originalRot,     // خانة 15 @vtbl 0x228
                            sprite.transform, player, randSlide:0f, isEventFromServer:false);
    return sprite.transform.parent.TransformPoint(originalPos);   // 0x68A3E58
}
```

* حلّ الخانات بالصيغة `slot=(offset−0x138)/16`: `0x278→20`, `0x258→18`, `0x248→17`, `0x228→15` ✅.
* المصفوفة `_originalEatingCardsTransformsRotations@0xC8` تُفهرَس بحجم عنصر `0xC` (Vector3):
  المكوّن z من `+0x28`، و`x,y` من `+0x20` (رأس مصفوفة il2cpp = بيانات عند `+0x20`)، مع
  فحص حدود (`cmp w0,w8; b.hs → throw`).
* **المُستدعي**: ✅ `CardGameVisualControls$$<PlayCard>g__CustomPlayCard|77_1` (`bl` في `0x530831C`)
  — أي أنّ موضع الهبوط يُحسَب داخل مسار اللعب المخصّص لكل ورقة.

## ٤. ⭐ `GetPlayerSlotIndex(KPlayer player) → int` — الأساس `0x5306D40` مقابل جكارو `0x51DB428`

### ٤٫١ الأساس (`CardGameVisualControls`، خانة 18) ✅

```csharp
protected virtual int GetPlayerSlotIndex(KPlayer player) {
    return ((CardGame)_game).Players.IndexOf(player);   // _game @0x40 ; get_Players 0x530ECB8
}
```

* فحص نوع `_game` مقابل `CardGame_TypeInfo` (`0x8CA8148`) قبل الاستعمال (نمط isinst il2cpp).
* `KGame$$get_Players` `0x530ECB8` ثم `List<object>.IndexOf` `0x3465664` على `player`.
* أي: **فهرس الخانة = ترتيب مقعد اللاعب** في قائمة لاعبي المباراة.

### ٤٫٢ 🛑 جكارو تُلغيه بالكامل (`JackarooCardGameVisualControls`، خانة 18) ✅

```asm
0x51DB428  ldr  w0, [x0, #0x198]   ; return this.CardIndex
0x51DB42C  ret
```

الحقل `0x198` = `<CardIndex>k__BackingField` (خاصّة `CardIndex`). الإلغاء **يتجاهل `player`
تمامًا** ويُعيد عدّادًا متسلسلًا يُزاد داخل `Jackaroo::PlayCard` (`0x51DB4B8`:
`[this+0x198] += 1`).

> ⭐ **الأثر المعماريّ**: في البلوت/الطرنيب «الخانة» = مقعد اللاعب (0..3). في **جكارو**
> «الخانة» = **رقم ورقة متسلسل**، فتتراصّ الأوراق الملعوبة تسلسليًّا (مروحة/كومة) لا حسب
> المقعد. هذا هو سبب اختلاف موضع الهبوط بين الألعاب رغم مشاركة `GetCardLandingWorldPosition`
> نفسه. ⚠️ يعني أنّ المصفوفة `_originalEatingCardsTransformsRotations` في جكارو تُفهرَس
> بـ`CardIndex`، لا بمقعد؛ فحص الحدود في §٣ يحميها من التجاوز.

## ٥. `GetSwayValue(SwayDirection) → float` — `0x5306F9C` ✅

قيمة تمايل عشوائيّة (درجات دوران) للورقة المجاورة عند الاصطدام. ثوابت `fmov` الفوريّة مقروءة
حرفيًّا، والنداء ذيليّ إلى `UnityEngine.Random$$Range` (`0x687B908`):

```csharp
private static float GetSwayValue(SwayDirection d) => d switch {
    DontSway (0) => 0f,
    SwayRight(1) => UnityEngine.Random.Range(-3f, -1f),   // fmov s0,#-3 ; s1,#-1
    SwayLeft (2) => UnityEngine.Random.Range( 1f,  3f),   // fmov s0,#1  ; s1,#3
    _            => throw new ArgumentOutOfRangeException("swayDirection", d, …)
};
```

* السلسلة `"swayDirection"` عند `0x8D485F0`، والاستثناء `ArgumentOutOfRangeException` (`0x8CA7290`).
* `SwayDirection` (`TypeDefIndex 988`): `DontSway=0, SwayRight=1, SwayLeft=2`.
* **المُستدعي**: ✅ ١٦ مرّة داخل `CardGameVisualControls.<>c__DisplayClass93_0$$<CardCollisionAnim>b__0`
  (`0x53090F8` وما يليه) — يطابق ما وُثِّق أنّ `CardCollisionAnim` (`0x5306A10`) يستدعيه.
* 🟡 **ملاحظة اتّجاه**: `SwayRight` يُنتج قيمة **سالبة** و`SwayLeft` **موجبة** — لافتة للنظر
  (يُحتمَل أنّ إشارة الدوران معكوسة اصطلاحًا مقابل الاسم). القيم تطابق ما في البلوت §٢٫٣ ⇒ لا تعارض.

## ٦. حدث `OnStageChanged` — `add 0x5300C44` · `remove 0x5300CF8` ✅

مُلحِقا حدث C# **قياسيان تمامًا** لحدث `CardGame`:

```csharp
// الحقل: 0x168
private Action<CardGameStage.CardGameStages, CardGameStage.CardGameStages, ISFSObject> OnStageChanged;
```

* `add`: حلقة CAS — `Delegate.Combine` (`0x566D800`) ثم `Interlocked.CompareExchange` على
  `this+0x168`، تُعاد حتى ينجح التبديل.
* `remove`: مثله بـ`Delegate.Remove` (`0x566D9F0`).
* النوع المُولَّد `Action<CardGameStages, CardGameStages, ISFSObject>` عند `0x8C9C3E8`.

> **الدلالة**: مراقبون خارجيّون يشتركون في تغيّر «مرحلة» المباراة؛ التوقيع يحمل
> **المرحلة السابقة + الجديدة + حمولة `ISFSObject`** من الخادم (SmartFox). لا منطق أعمق هنا —
> مجرّد بنية اشتراك. (المرحلة `CardGameStage.CardGameStages` هي آلة حالات اللعب المُوثَّقة في
> [§٠٩ — اليد والتفاعل](09-اليد-والتفاعل.md).)
