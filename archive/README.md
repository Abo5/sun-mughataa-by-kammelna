### ✅ كتالوج Addressables الثنائيّ — **محلول بالكامل**

`Data/Raw/aa/catalog.bin` (478,887 بايت) هو كتالوج Unity 6 الثنائيّ (`ContentCatalogData`
مسلسلًا عبر `BinaryStorageBuffer`). كان عائقًا في عدّة جولات؛ **وقد فُكّ الآن وتحقّق عمليًّا:**

#### الترويسة — ثماني كلمات
| الإزاحة | القيمة في هذا الملفّ | المعنى |
|---|---|---|
| `+00` | `0x0DE38942` | `Magic` |
| `+04` | `2` | `Version` |
| `+08` | `0x24` | `KeysOffset` — بداية جدول المفاتيح |
| `+0C` | `0x4E70` | `LocatorId` ⇒ `"AddressablesMainContentCatalog"` ✅ |
| `+10` | `0x4FB7` | `InstanceProvider` |
| `+14` | `0x5026` | `SceneProvider` |
| `+18` | `0x51A9` | `InitObjects` (مصفوفة ٤ مراجع) |
| `+1C` | `0x51BD` | `BuildResultHash` ⇒ `"75b007cb414da5d7c86c31b92235c168"` ✅ |

#### ⭐⭐⭐ القاعدة التي كانت مفقودة
**كل مرجع يشير إلى «جسم» يسبقه `u32` بطوله بالبايت عند `ref − 4` — والمصفوفات كذلك، لا السلاسل فقط.**
التحقّق: `+18` يشير إلى `0x51A9` وطولها ١٦ بايت مخزَّن عند `0x51A5` = ٤ مراجع بالضبط.
و**`0x24 + 20040 = 0x4E6C`** وهو بالضبط موضع بادئة طول `LocatorId` ⇒ جدول المفاتيح
هو `[0x24, 0x4E6C)` = **٥٠١٠ كلمة = ٢٥٠٥ زوجًا**.

> 🛑 **وهذا يصحّح التشخيص السابق.** لم يكن هناك «فهرس تجزئة» قطّ. سبب فشل كل المسوح السابقة
> أنّها بحثت عن مراجع تشير إلى **جسم** سلسلة المعرّف، بينما الكتالوج يشير إلى **كائن السلسلة**
> الذي يبدأ **قبل الجسم بـ`0x14` بايت**. المعرّفات كانت مُشارًا إليها دائمًا — في مكان لم أفحصه.
> و**الأزواج الـ٧٥٣ القديمة كانت تحفظ ذاتيًّا لا معنى لها** — أُلغيت.

#### جدول المفاتيح — `KeyEntry { u32 keyObject; u32 locationsArray; }`
كائن المفتاح له شكلان، يُفرَّق بينهما بأن `locationsArray == keyObject + 12`:

| الشكل | الشرط | طول السلسلة | جسم السلسلة |
|---|---|---|---|
| **أ** | `arr == K + 12` | بعد المصفوفة: `K + 12 + arrLen` | +٤ بعده |
| **ب** | غير ذلك | `K + 8` | `K + 0x0C` |

#### سجلّ الموقع — ٣٢ بايت
| الإزاحة | المعنى |
|---|---|
| `+00` | `InternalId` (مرجع سلسلة؛ قد يحمل راية `0x40000000`) |
| `+08` | `ProviderId` ⇒ `"…Provider"` |
| `+0C` | **مصفوفة التبعيّات** أو `0xFFFFFFFF` |
| `+14` | `Type` ⇒ مثلًا `"IAssetBundleResource"` |
| `+18` | `PrimaryKey` |

> ⚠️ **الرايات في البتّات العليا**: بعض المراجع تحمل `0x40000000` (سلسلة مقطَّعة/موروثة).
> **يجب قناعها بـ`& 0x0FFFFFFF`** قبل الاستعمال — وهذا سبب إضافيّ لفشل المحاولات السابقة.

#### ⭐⭐ سلسلة الربط `GUID → حزمة`
```
مفتاح (٣٢ hex)  →  موقع واحد  →  مصفوفة التبعيّات @+0x0C  →  مواقع الحزم  →  InternalId لكلٍّ
```

#### النتيجة والتحقّق
| المقياس | القيمة |
|---|---|
| مفاتيح | **٢٥٠٥** |
| أسماء حزم | ٧٥٧ |
| معرّفات أصول (٣٢ hex) | **٨٤٩ — كلّها مرتبطة بحزمها** |

## ما تم إنجازه

1. **تحميل الأداة** `mobrecon-go` من GitHub وتشغيلها على الملف.
2. **فك ضغط الـ IPA بالكامل** — 1018 ملف داخلي (كل الملفات بدون استثناء).
3. **استرجاع بنية الكود** عبر `Il2CppDumper` (نسخة fork تدعم metadata v39 الخاص بـ Unity 6).
4. **فصل كود اللعبة الخاص** (`KammenlaAssembly.dll`) عن كود المكتبات الخارجية.
5. **استرجاع أجسام الدوال الفعلية (IL Recovery)** عبر `Cpp2IL` (نسخة 2022.1.0 المبنية من المصدر، تدعم Unity 6000.3.8f1 / metadata v39) — نجح في استرجاع أجسام **54,148 دالة** بنسبة 100%.
6. **تفكيك الكود إلى C# حقيقي** عبر `ILSpy` (مكتبة ICSharpCode.Decompiler) — كود اللعبة بأجسام دوال فعلية.

### ⭐ أهم نتيجة: الكود المصدري الكامل للعبة

```
source-code/cpp2il-cs-full/KammenlaAssembly/   ← ★ 4205 ملف C# (244MB) بأجسام الدوال الفعلية
```

هذا هو **الكود المصدري الحقيقي للعبة** — ليس مجرد أسماء كلاسات، بل منطق الدوال
الفعلية (الشروط، الحلقات، الاستدعاءات). بعض العمليات العامة (generics/boxing) تظهر
بعلامات `// Unknown result type` لأنها تُفقد أثناء التحويل إلى native، وهذا متوقع في
استرجاع IL2CPP.

## ملاحظة مهمة حول "الكود المصدري"

هذا التطبيق مبني على **Unity بمعمارية IL2CPP**، أي أن كود C# الأصلي تم تحويله إلى
كود أصلي (native machine code) وقت التجميع. لذلك:

- ✅ **تم استرجاعه بالكامل**: أسماء الكلاسات والدوال والحقول والخواص والتعدادات
  والـ attributes وكل النصوص (strings) والروابط والمفاتيح — وهذا ما في `dump.cs` و `source-code/KammenlaAssembly-source.cs`.
- ⚠️ **لا يمكن استرجاعه**: أجسام الدوال الأصلية (method bodies) لأنها تحولت إلى
  تعليمات ARM أصلية. لاسترجاع منطق الدوال بدقة يلزم تفكيك (decompile) الكود الأصلي
  بأدوات مثل Ghidra/IDA على ملف `UnityFramework`.

كل الملفات مقروءة وغير مشفرة — تم التحقق من عدم وجود أي حماية/تشفير يمنع القراءة.
