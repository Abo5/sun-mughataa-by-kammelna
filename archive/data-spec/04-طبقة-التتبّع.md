# ٠٤ — طبقة التتبّع والتحليلات (`DataTracking`)

[↩ الفهرس](README.md)

> **ما البيانات المُرسَلة، وإلى أين.** واجهةٌ واحدة (`Tracker`) تُغذّي **مُنصّة تحليلات حيّة
> واحدة فقط — GameAnalytics** عبر قائمة استراتيجيّات، بينما تُستعمَل **Firebase مباشرةً**
> (لا عبر استراتيجيّة) لسِمات ملف اللاعب ومُعرّف Crashlytics فقط. الطبقة تعمل **في الإنتاج
> حصرًا** (`Config.IsProduction`). يبني هذا الفصل على [`sound-spec/01 §٨`](../sound-spec/01-الصوت-والمعلّقون.md)
> الذي أثبت أن عائلة `Preference*` في `TrackerLibrary` كودٌ ميّت وأن `Tracker.UserProfile`
> يقرأ **سِمات لقطة** لا أحداث تغيير — وأضيف هنا اكتشافًا أكبر: **`FirebaseAnalyticsStrategy`
> بأكملها كودٌ ميّت.**

## ✅ ما تحقّقتُ منه بنفسي

| الادّعاء | النتيجة |
|---|---|
| **الاستراتيجيّة الوحيدة المُسجَّلة** | ✅ `Tracker.Initialize` @`0x519240C` يُنشئ ويُضيف `GameAnalyticsStrategy` **فقط** إلى قائمة `_strategies` `[BIN:]` |
| **`FirebaseAnalyticsStrategy` كلّها ميّتة** | ✅ مسحُ الثنائي كلّه (`bl`+`b`): `.ctor` @`0x51A6A90` له **صفر مستدعٍ**؛ `AdEvent`/`PurchaseEvent`/`DesignEvent`/`ResourceEvent`/`SetDimensions` كلٌّ **صفر**؛ `TrimValue` **صفر**؛ `SanitizeEventName` مستدعٍ واحد (من `DesignEvent` الميّت نفسه). لا instance ⇒ لا إرسال ظاهريّ `[BIN:]` 🟡→✅ |
| **`GameAnalyticsStrategy.ctor`** @`0x51A71D0` | ✅ مستدعٍ واحد بالضبط عند `0x519248C` داخل `Initialize` `[BIN:]` |
| **`AdjustStrategy` كلّها ميّتة أيضًا** | ✅ مسحُ `bl`+`b` على `.ctor` @`0x51A47C0` في كلّ `__TEXT`: **صفر مستدعٍ**. ومعها `AdjustEventSettings` بتعريفاتها الأربعة (`Design`/`Resource`/`Purchase`/`AdEventDefinition`) وبِطاقاتها — **لا وجهة Adjust للأحداث** `[BIN:]` |
| **`Initialize` كلّها ٢٥٢ بايتًا** | ✅ مفكوكة تعليمةً تعليمة: بوّابة `strb w8,[x20,#0xc1a]` (تهيئة مرّة واحدة) ← `GameAnalyticsStrategy..ctor` ← `List.Add` مُضمَّنة (المسار السريع `str x20,[x0,#0x20]!`، والاحتياطيّ `List<object>.AddWithResize` @`0x3464528`). **لا منشئ استراتيجيّة ثانٍ في الدالّة** `[BIN:]` |
| بوّابة الإنتاج | ✅ `DesignEvent`/`UpdateDimensions`/`SetActiveGame` تُختبَر جميعًا بـ`Config.IsInitialized` **و**`Config.IsProduction` قبل أي إرسال `[BIN:]` |
| اسم حدث التصميم = مفاصل بنقطتين | ✅ `GetEventString` @`0x51A2E5C`: `Enum.ToString` لكلٍّ من Context·Feature·Placement·Outcome + label ← `Where` (إسقاط الفارغ) ← `JoinToString(":")` `[BIN:]` |
| Firebase = سِمات + Crashlytics فقط | ✅ داخل `Tracker` لا `FirebaseAnalytics.LogEvent` قطّ؛ فقط `SetUserProperty` (×12 موضع) و`Crashlytics.SetUserId` في `SetActiveGame` `[BIN:]` |
| كتالوج سِمات `UserProfile` | ✅ مُستخرَج من `0x5193EE0` (السلاسل والنداءات أدناه) `[BIN:]` |
| الأبعاد الثلاثة لـGameAnalytics | ✅ `DimensionsModel..ctor` @`0x5191FF8`: [0]=`Subscribed`/`Non-Subscribed` · [1]=رتبة اللاعب · [2]=اللعبة الحاليّة `[BIN:]` |
| بوّابة «مرّة يوميًّا» لـ`UserProfile` | ✅ `HasTrackedUserProfileToday` (يقرأ `LastUserProfileTrackDate` عبر `Prefs.GetDate`) + `UpdateTrackUserProfileDate` `[BIN:]` |
| تنقية اسم الحدث لـFirebase | ✅ `SanitizeEventName` @`0x51A5F04`: بادئات محجوزة `firebase_`/`google_`/`ga_` ← `k_`؛ سقف 40 محرفًا `[BIN:]` (لكنّها في مسارٍ ميّت) |
| التعدادات | ✅ من `dump.cs`/المصدر: `TrackingContext`(11) · `TrackingFeature`(51) · `TrackingPlacement`(57) · `TrackingOutcome`(≈300) · `ResourceFlowType`(3) · `ResourceCurrency`(2) `[ENUM:]` |

> ⚠️ **الدالّتان الأكبر في التكليف — `FirebaseAnalyticsStrategy::*` — تنتميان لصنفٍ ميّت.**
> وثّقتُها كما طُلِب («ما البيانات وإلى أين»)، لكنّ الوجهة الفعليّة لأحداث اللعبة هي
> **GameAnalytics** وحدها. عالِج كتالوج Firebase أدناه على أنه **التصميم المقصود المُعطَّل**، لا مسارًا حيًّا.

## ١. الخريطة

```
   مواقع الاستدعاء في اللعبة (Store, Preferences, SFS, AdsController, …)
                     │  TrackerLibrary.XxxEvent() تبني ITrackEvent
                     ▼
      ┌──────────────  DataTracking.Tracker (واجهة ساكنة)  ──────────────┐
      │                                                                   │
      │  Initialize()               بوّابة كلّ إرسال:                     │
      │   _strategies = [ GameAnalyticsStrategy ]   ← الوحيدة!            │
      │                              Config.IsInitialized && IsProduction │
      │                                                                   │
      ├── DesignEvent / PurchaseEvent / ResourceEvent / AdEvent ──────────┤
      │        foreach s in _strategies:  s.Xxx(...)                      │
      │                     │                                             │
      │                     ▼                                             │
      │            GameAnalyticsStrategy  ──►  GameAnalytics SDK          │
      │              NewDesignEvent / NewBusinessEvent /                  │
      │              NewResourceEvent / NewAdEvent / SetCustomDimension   │
      │                                                                   │
      ├── UserProfile()  (مرّة/يوم) ──►  FirebaseAnalytics.SetUserProperty × ~11
      │                              ──►  + أحداث تصميم لقطة (Preferences)│
      │                                                                   │
      └── SetActiveGame() ──►  SetUserProperty("Active_Game")             │
                          ──►  Firebase.Crashlytics.SetUserId(userId)     │
                                                                          
   ✗ FirebaseAnalyticsStrategy (AdEvent/Purchase/Design/Resource/SetDimensions)
     — صنفٌ كامل، صفر instance، صفر مستدعٍ ⇒ لا يصل إليه أي حدث.
   ✗ AdjustStrategy (+ AdjustEventSettings بتعريفاته الأربعة)
     — كذلك: صفر instance، صفر مستدعٍ ⇒ لا يصل إليه أي حدث.
```

**حارسٌ إضافيّ:** كلّ نداء `SetUserProperty`/`SetUserId` مسبوقٌ بفحص `KUtil.NoPlayServices`
(يُتخطّى إن غابت خدمات Google Play/Firebase) `[BIN:]`. ⭐ **الخلاصة الجوهريّة:** أحداث اللعبة
(تصميم/شراء/موارد/إعلانات) تذهب إلى **GameAnalytics فقط**؛ Firebase يتلقّى **سِمات لاعب +
مُعرّف انهيار** لا غير.

## ٢. ⭐ الاكتشاف الأكبر: `FirebaseAnalyticsStrategy` كودٌ ميّت بالكامل

`[BIN:]` مسحتُ الثنائي (`0x100000`–`0x8000000`) لكلٍّ من `bl` (`0x94000000`) و`b`
(`0x14000000`) نحو كلّ دوالّ الصنف:

| الدالّة (`0x51A…`) | مستدعو `bl`+`b` |
|---|---|
| `.ctor` @`0x51A6A90` | **0** (لا instance يُخلق أبدًا) |
| `AdEvent` @`0x51A4CB0` | 0 |
| `PurchaseEvent` @`0x51A522C` | 0 |
| `DesignEvent` @`0x51A5930` | 0 |
| `ResourceEvent` @`0x51A620C` | 0 |
| `SetDimensions` @`0x51A6820` | 0 |
| `SanitizeEventName` @`0x51A5F04` | 1 (من `DesignEvent` الميّت) |
| `TrimValue` @`0x51A58B0` | 0 |

> 🛑 **قاعدة الكود الميّت مُطبَّقة بحذر:** هذه دوالّ ظاهريّة (تُنفّذ `IAnalyticsStrategy`)،
> و«صفر `bl` مباشر» وحده لا يُثبت موتها لأنها قد تُنادى عبر فتحة ظاهريّة. **لكن** الـ`.ctor`
> نفسه بلا مستدعٍ (`bl`+`b`=0) ⇒ **لا instance قطّ**، والصنف **غير مُضاف إلى `_strategies`**
> (المضاف الوحيد `GameAnalyticsStrategy`) ⇒ لا مسار ظاهريّ يبلغه. ⇒ الصنف كلّه ميّت ✅.
> غياب أي `new FirebaseAnalyticsStrategy` في مصدر cpp2il كلّه يؤكّده `[CS:]`.

**الأثر العمليّ لإعادة البناء:** الأصل *يملك* منطق إرسال Firebase كاملًا (أحداث + معاملات
+ تنقية أسماء) لكنه **موصولٌ خارج الدارة**. من يعيد البناء يقرّر: إمّا وصله (Firebase +
GameAnalytics) أو حذفه (GameAnalytics فقط، كالسلوك الحاليّ).

## ٣. كتالوج الأحداث الحيّة (وجهتها GameAnalytics)

`Tracker` يبني الحدث بـ`TrackerLibrary.XxxYyy(...)` (مئات المصانع الساكنة، كلٌّ يُنشئ
`TrackerEvent` من أربعة تعدادات + label + value)، ثم يُمرّره إلى كلّ استراتيجيّة. الترجمة إلى GameAnalytics:

### ٣.١ حدث التصميم — `Tracker.DesignEvent` @`0x5192C70` → `GameAnalytics.NewDesignEvent`

* **اسم الحدث** يُبنى في `TrackerEvent.GetEventString` @`0x51A2E5C` `[BIN:]`:
  ```
  name = JoinToString(":",  [Context, Feature, Placement, Outcome, label]
                            .Select(Enum.ToString)
                            .Where(s => s != ""))
  ```
  ⇒ اسمٌ **هرميّ بنقطتين** مثل `Monetization:InAppPurchase:Shop:MainShopViewed`
  (GameAnalytics يدعم هرميّة النقطتين حتى ٥ مستويات أصلًا — وهذا سبب اختيار الفاصل `:`).
* **القيمة الاختياريّة** `GetEventValue()` تُمرَّر كوسيط ثانٍ (`NewDesignEvent(name, value)`) عند وجودها.
* يُسجَّل محلّيًّا عبر `KLogger.LogAnalytics` بلون `#FFD54F` (`#4FC3F7` لسياق `[CLAN]`) `[BIN:]`.

### ٣.٢ حدث الشراء — `Tracker.PurchaseEvent` @`0x51927B8` → `GameAnalytics.NewBusinessEvent`

`[CS:]` `NewBusinessEvent(currencyCode, amount, friendlyName(purchaseType), itemId, shop)`
حيث `amount` قرشيّ (السعر × ١٠٠ عادةً في GA)، و`purchaseType` من `TrackerPurchase` `[ENUM:]`:
`None=0 · AcesPack=12001 · Subscriptions=12002 · CodeActivation=12003 · BuyForFriend=12004`.

### ٣.٣ حدث الموارد — `Tracker.ResourceEvent` @`0x5193270` → `GameAnalytics.NewResourceEvent`

`[CS:]` `NewResourceEvent((GAResourceFlowType)flowType, friendlyName(currency), amount, friendlyName(itemType), itemId)`.
* `ResourceFlowType` `[ENUM:]`: `None=0 · Source=1 · Sink=2` (كسب/إنفاق).
* `ResourceCurrency` `[ENUM:]`: `None=0 · Aces=1` (العملة الوحيدة المُتتبَّعة).
* `ResourceItemType`: `IAP=1` (+قيم أخرى).
* `ResourceItemId` `[ENUM:]` (مصدر/مصرف الأيسات — كتالوج كامل): `Code=1 · Minigame=2 · BombClaim=3
  · RoomCreate=4 · RoomJoin=5 · TournamentCreate=6 · TournamentJoin=7 · Fasttrack=8 · AdSkip=9
  · Subscription=10 · CardSlap=11 · SawaSlap=12 · Bomb=13 · Transfer=14 · ClanCreate=15 ·
  ClanVaultDeposit=19 · AcesPack=100 · Theme=101 · Card=102 · Pattern=103 · Emote=104 ·
  Unique=105 · Gift=106 · Like=107`. ⇒ خريطةٌ كاملة لاقتصاد الأيسات (مصادره ومصارفه).

### ٣.٤ حدث الإعلان — `Tracker.AdEvent` → `GameAnalytics.NewAdEvent`

`[CS:]` `NewAdEvent(adAction, adType, adSDK, adPlacement)` — كلها تُمرَّر كما هي (SDK نصّ،
والبقيّة تعدادات `AdAction`/`AdType`/`AdPlace`).

### ٣.٥ الأبعاد المخصّصة — `Tracker.UpdateDimensions` @`0x51969C0` → `SetCustomDimension01..03`

`DimensionsModel.DimensionArray[0..2]` (من `..ctor` @`0x5191FF8`) `[BIN:]`:

| البُعد | المصدر | القيم |
|---|---|---|
| **01** = `[0]` | `SFSKammelnaUserExtensions.IsSubscribed` | `Subscribed` / `Non-Subscribed` |
| **02** = `[1]` | `GetRank` → `EnumExtensions.GetFriendlyName(PlayerRank.Ranks)` | اسم الرتبة الوديّ |
| **03** = `[2]` | `Preferences.CurrentGame` (Enum.ToString) | `Baloot`/`Tarneeb`/`Jackaroo`… |

تُبثّ لكلّ استراتيجيّة عبر تكرار `_strategies` (⇒ GameAnalytics فقط)، وتُستدعى من جلسة
الخادم `SFS` وعند تبديل اللعبة `[BIN:]`.

يُرسِل نوعين:

|---|---|

| `Active_Card` | اسم البطاقة المملوكة الفعّالة، وإلا `Default` |
| `Active_Room` | اسم ثيم الغرفة الفعّال، وإلا `Default` |

| `Clan_Tier` | مستوى القبيلة، وإلا `None` |

`Enabled`/`Disabled` (وأزواج أخرى):

### ٤.٣ مُعرّف Crashlytics — `Tracker.SetActiveGame` @`0x5196FA8` `[BIN:]`

**تُربَط تقارير الانهيار بمُعرّف اللاعب.**

## ٥. تنقية أسماء أحداث Firebase — `SanitizeEventName` @`0x51A5F04` ⚠️

`[BIN:]` (في المسار الميّت §٢، لكنّها المنطق المُصمَّم لتوليد أسماء صالحة لـFirebase):

1. `StringBuilder`: يمرّ على المحارف، ويُبقي `IsLetterOrDigit` فقط (الباقي يُبدَّل/يُسقَط —
   ومنه النقطتان `:` من الاسم الهرميّ).
2. إن لم يكن أوّل محرف حرفًا (`IsLetter`) ⇒ `Insert("k_")` في المقدّمة (Firebase يشترط بدء الاسم بحرف).
3. إن بدأ بأحد البادئات **المحجوزة** `firebase_` · `google_` · `ga_` ⇒ `Concat("k_", …)`.
4. سقفٌ: `Substring(0, 40)` (`MaxEventNameLength=40`).

ومعاملات Firebase (لو كان المسار حيًّا) `[BIN:]`:

| الحدث (Firebase) | المفتاح=القيمة |
|---|---|
| `ad_event` | `ad_sdk`=نصّ · `ad_action`/`ad_type`/`ad_placement`=Enum.ToString |
| (تصميم) `<sanitized>` | `raw_name`=الاسم الأصليّ الهرميّ (سقف 100) · `value`=float عند وجوده |
| (شراء) | `purchase_type`=Enum · `item_id` · `price` · `currency` · `shop` (كلها سقف 100 عبر `TrimValue`) |
| (موارد) | `item_type` · `item_id` · `amount` · `currency` · flow |

`TrimValue` = `Substring(0, 100)` (`MaxParamValueLength=100`). سِجِلّ تنقيح داخليّ عبر
`KLogger.LogAnalytics` بصيغ مثل `"{0}AdEvent → ad_event | sdk={1} action={2} type={3} placement={4}"` `[BIN:]`.

> 🚩 **عِلّة في الأصل:** لأنّ الاسم الهرميّ (`A:B:C:D`) يُنقّى بحذف النقطتين، فإن اسمَي حدثين
> يختلفان بمواضع النقطتين فقط قد ينهاران إلى اسمٍ واحد في Firebase — لكنّ هذا موضعيّ لأنّ المسار ميّت أصلًا.

## ٦. الأسرار والمُعرّفات ⚖️

* **Firebase**: التكامل يحمّل `google-services`/`GoogleService-Info` (معرّفات مشروع Firebase +
  مفتاح API). **لم أطبع أيًّا منها.** موضع التحميل: تهيئة Firebase عند الإقلاع (خارج نطاق هذا
  الفصل)، لا في `DataTracking`.
* **GameAnalytics**: مفاتيح اللعبة/السرّ (`gameKey`/`secretKey`) تُحمَّل في تهيئة `GameAnalyticsSDK`
  (لا في `Tracker`). ذُكِر وجودها فقط، دون نقل.
* لا توكنات ولا مفاتيح توقيع في مسار التتبّع نفسه.

## ٧. تعدادات التتبّع (مرجع) `[ENUM:]`

* `TrackingContext` (11): `Onboarding · Account · Navigation · Social · Communication ·
  RewardedEngagement · Monetization · Game · Preferences · Diagnostic · Dev`.
* `TrackingFeature` (51): من `FirstUseExperience`/`Register`/`Login` … حتى `Clan`/`UiNav`/`MarketingGrant`.
* `TrackingPlacement` (57): من `Background`/`Onboarding`/`SignIn` … حتى سلسلة `Clan*` (`ClanLanding`…`ClanLockedLevel`).
* `TrackingOutcome` (≈300): أكبر تعداد — يغطّي كلّ حدث UI/لعبة/قبيلة/تسويق. أمثلة جوهريّة:
  `RegisterSucceeded · MatchedInSeconds · CurrencyBought · EmoteSent · GameSound · Cards ·
  ClanCreated · MarketingGrantRedeemed`. **الاسم النهائيّ للحدث = تركيب Context+Feature+Placement+Outcome.**

> هذه التعدادات هي **قاموس التحليلات الكامل**: كلّ ما تعرفه اللعبة عن سلوك اللاعب مُعبَّرٌ
> عنه بتوليفة من هذه الأربعة. من أراد إعادة بناء التتبّع يبدأ من هنا.

## ٩. 🛑 تصحيح لأرشيف الاقتصاد

[`economy-spec/03` §٨ بند ٢](../economy-spec/03-المشتريات-داخل-التطبيق.md) يقول إنّ `DataTracking`
يوزّع كل حدث على **ثلاث وجهات متوازية** (`FirebaseAnalyticsStrategy` · `GameAnalyticsStrategy` ·
`AdjustStrategy`). **هذا غير صحيح** — والصحيح أنّ الأصناف الثلاثة موجودة في الثنائي فعلًا،
لكن **واحدًا منها فقط يُنشأ**:

| الاستراتيجيّة | `.ctor` | مستدعو `.ctor` (`bl`+`b` في كلّ `__TEXT`) | الحالة |
|---|---|---|---|
| `GameAnalyticsStrategy` | `0x51A71D0` | **١** — `Tracker.Initialize` @`0x519248C` | ✅ حيّة |
| `FirebaseAnalyticsStrategy` | `0x51A6A90` | **٠** | 🛑 ميّتة |
| `AdjustStrategy` | `0x51A47C0` | **٠** | 🛑 ميّتة |

⇒ البند المعلَّق هناك («كيف يُوزَّع الحدث على الاستراتيجيات الثلاث») **ساقط بأصله**: التوزيع
حلقةٌ على قائمة فيها عنصر واحد. وبند «الوجهة النهائية للتتبّع» يُقرأ من هذا الفصل لا من هناك.

> **القاعدة المطبَّقة**: الفصل المتأخّر — وهو نتيجة تدقيق لاحق بكود الآلة — هو المرجع.

## ٨. خلاصة لإعادة البناء

| العنصر | القرار في الأصل | ما يجب استنساخه |
|---|---|---|
| **المنصّة الحيّة** | GameAnalytics فقط (استراتيجيّة واحدة مُسجَّلة) | سجّل استراتيجيّاتك في `Initialize`؛ الواجهة تكرّرها |
| **Firebase** | سِمات لاعب + `Crashlytics.SetUserId` فقط؛ استراتيجيّة أحداثه **ميّتة** | قرّر: صِل استراتيجيّة Firebase أو احذفها |
| **بوّابة الإرسال** | `IsInitialized && IsProduction` + `NoPlayServices` | لا تتبّع في التطوير؛ تخطٍّ صامت بلا خدمات المتجر |
| **اسم حدث التصميم** | هرميّ `Context:Feature:Placement:Outcome[:label]` بفاصل `:` | حافظ على الهرميّة (GA) وأضِف تنقية للوجهات التي تمنع `:` |
| **الأبعاد الثلاثة** | اشتراك · رتبة · لعبة | ابثّها عند تبديل اللعبة وجلسة الخادم |
| **الموارد** | عملة واحدة `Aces`؛ كتالوج `ResourceItemId` (مصادر ١–١٩، مصارف ١٠٠–١٠٧) | خريطة اقتصاد الأيسات جاهزة أعلاه |
| **الشراء** | `NewBusinessEvent`؛ ٤ أنواع (`AcesPack`/`Subscriptions`/`CodeActivation`/`BuyForFriend`) | — |
| **ملف اللاعب** | لقطة مرّة/يوم عند فتح المتجر (١١ سِمة + ~١٥ لقطة تفضيل) | لا أحداث تغيير لحظيّة للتفضيلات |
| **الحدود** | اسم ≤ 40، قيمة ≤ 100 (قيود Firebase) | التزمها إن استهدفت Firebase |
