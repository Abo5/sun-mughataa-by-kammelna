# ٠٢ — حفظ الملفّات المحليّة: `SaveLoadUtils` · `FileUtils` · `CompressUtil`

[↩ الفهرس](README.md)

> نظام حفظ عامّ المظهر (قوالب عامّة، ضغط، إلغاء، تحميل متوازٍ، مسار ويب بديل)
> **مستهلكه الوحيد في اللعبة كلّها هو `JackarooCustomRules`.**
> هذا الفصل يوثّقه كما هو، ويفصل ما يعمل فعلًا عمّا بُنِيَ ولم يُستعمل.

## ✅ ما تحقّقتُ منه بنفسي
| الادّعاء | النتيجة |
|---|---|
| عدد المستهلكين | ✅ **واحد**: `Save` ←١ · `LoadItems` ←١ · `LoadItemsWeb` ←١ · `Delete` ←١ — كلّها `JackarooCustomRules` |
| الضغط مُفعَّل؟ | ✅ **لا** — `useCompression = 0` في المواضع الثلاثة: `0x5119CD8` · `0x511A170` · `0x511A900` |
| المسار | ✅ `Config.CachePath` + `Preferences.CurrentGame` + `"savedCustomRules"` @`0x5118BEC` |
| الامتداد والفاصل | ✅ `".json"` @`0x5119C38` · `"_"` @`0x5119C44` |
| فرع الويب | ✅ `KUtil.GetPlatform() == 3` أي `Platform.Web` @`0x5118F9C` |

> 🛑 **تصحيح لملاحظة سابقة في هذه الجلسة.** قلتُ إنّ `SaveLoadUtils` «يضغط خلافًا لنظام إعادة اللعب».
> هذا خطأ: الضغط **موجود كفرع ومُعطَّل عند كل مستدعٍ**. الملفّات على القرص **JSON صريح غير مضغوط**،
> تمامًا كما في [إعادة اللعب](../replay-spec/01-نظام-إعادة-اللعب.md).

## ٢. ⭐ تطهير اسم الملفّ — الجزء المشترك بين `Save` و`Delete`

نفس المتتالية حرفيًّا في الدالّتين (`0x3021708`+ و`0x4EE71E4`+):

```csharp
name = string.Join( "", name.Split( Path.GetInvalidFileNameChars() ) );   // حذف لا استبدال
ext  = ext.StartsWith(".") ? ext : "." + ext;                            // "." @0x3021794
full = Path.Combine( savingPath, name + separator + id + ext );
```

> ⭐ **الحروف الممنوعة تُحذف لا تُستبدَل** (`Join("")` لا `Join("_")`). النتيجة: اسمان مختلفان
> يمكن أن يتصادما — `"a/b"` و`"ab"` يعطيان الملفّ نفسه. في جاكارو هذا لا يظهر لأن الفاصل
> `"_" + CreationTime` يميّز، لكنّ أي استعمال آخر لهذه الدالّة يجب أن يحسب هذا.
>
> ⚠️ `Path.GetInvalidFileNameChars()` **يختلف بين المنصّات** (على ويندوز أطول بكثير منه على iOS).
> اسم مُطهَّر على منصّة قد لا يُطابِق نفسه على أخرى.

`IsNullOrWhiteSpace` يُفحَص **مرّتين** في مقدّمة كلٍّ من `Save` و`Delete` (`0x3021694`/`0x30216A4`
و`0x4EE71B0`/`0x4EE71C0`) — على الاسم والمسار.

`Delete` يفحص `File.Exists` قبل الحذف (`0x4EE7298` · `0x4EE72C8`).

## ٤. ⭐⭐ `LoadItems` — تحميل غير متزامن متوازٍ

`LoadItems` نفسها 344B فقط: `AsyncTaskMethodBuilder.Create` → `Start<d__1>` → `get_Task`.
العمل كلّه في `<LoadItems>d__1.MoveNext` @`0x45A4058`:

```
await Task.Run( () => { … } )                      ; 0x45A4224   ← يخرج عن خيط اللعبة
itemsToReturn.Sort( comparison )                   ; 0x45A4338   ← بعد العودة، على خيط اللعبة
```

داخل الـ`Task.Run` — `<LoadItems>b__0` @`0x31DB2E4`:
```
paths = FileUtils.ReadFiles( savingPath, fileExtension )        ; 0x31DB404
opts  = new ParallelOptions { MaxDegreeOfParallelism = … ,      ; 0x31DB464
                              CancellationToken     = … }
Parallel.ForEach( paths, opts, b__1 )                          ; 0x31DB50C
```

ولكل ملفّ — `<LoadItems>b__1` @`0x31DBA4C`:
```
نصّ = محتوى الملفّ
إن useCompression:  نصّ = CompressUtil.Decompress(نصّ)          ; 0x31DBAB8
item = JsonConvert.DeserializeObject<T>(نصّ, settings)          ; 0x31DBAF8
Monitor.Enter(قُفل)                                            ; 0x31DBB24
    itemsToReturn.Add(item)                                    ; 0x31DBB94
Monitor.Exit(قُفل)                                             ; 0x31DBB0
catch (e):  Debug.LogWarning("Failed to process file: " + path + ". Error: " + e)  ; 0x31DBD04
```

> ⭐⭐ **قراءة وفكّ تسلسل متوازيان، وإضافة محميّة بـ`Monitor`، وترتيب واحد في النهاية.**
> `List<T>` غير آمن للخيوط، و`Monitor` هنا هو الفرق بين هذا وبين عطب عشوائيّ.
> لو أُعيد بناء هذا بـ`ConcurrentBag` لتغيّر ترتيب الإدخال — لا يهمّ هنا لأن `Sort` يلحق.
>
> ⭐ **عزل الأخطاء لكل ملفّ**: ملفّ تالف واحد ينتج `LogWarning` ويُتخطّى؛ بقيّة الحفظات تُحمَّل.
> نموذج أفضل من «حفظة واحدة تالفة تُسقط القائمة كلّها».

### معالجة الاستثناءات في `MoveNext` (`0x45A4444`–`0x45A4564`)
ثلاثة فروع مميَّزة:
1. `OperationCanceledException` → `Debug.LogError`
2. `AggregateException` → `LogError` ثم **تعداد `InnerExceptions`** (`ReadOnlyCollection.GetEnumerator` @`0x45A452C`) و`LogError` لكلٍّ
3. `Exception` عامّ → `builder.SetException` @`0x45A474C`

> 🟡 الفرع الثاني ضروريّ: `Parallel.ForEach` يلفّ كل أخطاء العاملين في `AggregateException` واحد،
> وبلا تعداد `InnerExceptions` يضيع السبب الحقيقيّ.

### `FileUtils.ReadFiles` @`0x4EDFBC4` (600B)
```csharp
new DirectoryInfo(path).GetFiles( "*" + fileTypeExtension )   // "*" @0x4EDFC44
   .Select( f => f.FullName )                                  // Func<FileInfo,string>
```
مع وسيط `bool searchInSubDirectories = false`.

## ٥. `LoadItemsWeb` — البديل للـWebGL

`LoadItemsWeb` @`0x3021410` كوروتين (`IEnumerator`) لا `Task`. سببه أنّ
`System.IO` و`Task.Run` غير متاحين على WebGL.

`JackarooCustomRules.Init` @`0x5118EF4` يفرّق بينهما:
```asm
bl   KUtil$$GetPlatform      ; 0x5118F98
cmp  w0, #3                  ; Platform.Web
b.ne #0x51190C8              ; ← غير الويب: LoadItems (async)
bl   CoroutineDummy$$get_Instance   ; ← الويب: StartCoroutine(LoadItemsWeb)
```
`enum Platform { Unknown, Android, IOS, Web, Huawei }` ⇒ **`3 == Web`** ✅

> ⭐ `CoroutineDummy.Instance` @`0x4EBCA3C` هو حامل كوروتينات عامّ — يسمح لصنف `static`
> بتشغيل كوروتين بلا `MonoBehaviour` خاصّ به.

## ٦. `CompressUtil` — موجود وغير مُستعمَل من هذا المسار

```csharp
enum CompressionAlgorithm { Brotli, GZip }        // Brotli هو الافتراضيّ
```

| الدالّة | العنوان |
|---|---|
| `Compress(string, algo)` | `0x4EBBD84` |
| `CompressToString(byte[], algo)` | `0x4EBBE54` |
| `Compress(byte[] → …)` النواة | `0x4EBBEF8` |
| `Decompress(string, algo)` | `0x4EBC424` |
| النواة العكسيّة | `0x4EBC4FC` |

النواة @`0x4EBBEF8`:
```
MemoryStream ×٢                                   ; 0x4EBBF6C · 0x4EBBF8C
→ GZipStream   إن algo == GZip                    ; 0x4EBBFF4
  BrotliStream إن algo == Brotli (الافتراضيّ)      ; 0x4EBC01C
→ Stream.CopyTo                                   ; 0x4EBC044
→ Convert.ToBase64String
```
والعكس: `Convert.FromBase64String` @`0x4EBC47C` → فكّ الضغط → `Encoding.UTF8`.

> ⭐ الخرج **Base64 لا بايتات خام** — أي أنّ الضغط لو فُعِّل لكان يستعيد ٣٣٪ من مكسبه فورًا.
> 🟡 هذا وحده تفسير معقول لتعطيله عند كل مستدعٍ: على ملفّ قواعد صغير، Brotli + Base64
> قد لا يوفّر شيئًا يُذكَر.

## ٧. المستهلك الوحيد — `JackarooCustomRules`

### المسار
```
get_SavingPath @0x5118B90
  = Path.Combine( Config.CachePath,                       ; 0x5118C28
                  Preferences.CurrentGame.ToString(),     ; 0x5118C4C + Enum.ToString
                  "savedCustomRules" )                    ; 0x5118BEC
```
و`Config.get_CachePath` @`0x5099254` = `string.Format("{0}/{1}/", …, Config._environmentFolder)`
— أي أنّ **الحفظات معزولة ببيئة الخادم** (إنتاج / تجربة) وبنوع اللعبة.

### الملفّ
```
{Name}  +  "_"  +  {CreationTime}  +  ".json"
```
`Save` @`0x5119BD4` يضبط `save.CreationTime = creationTime.Value` (`str x0, [x19, #0x10]` @`0x5119C70`)
قبل النداء إن كان الوسيط `long?` غير فارغ، ثم:
```asm
mov x1, x20     ; fileName  = save.Name   (الحقل 0x18)
ldr x2, ".json" ; extension
bl  0x5118b90   ; savingPath
mov w6, #0      ; useCompression = false   ← 🛑
bl  0x3021614   ; SaveLoadUtils.Save<object>
```

### سِجِلّ الحفظ
`JackarooCustomRulesSave`:
| الحقل | الإزاحة | النوع | مفتاح JSON |
|---|---|---|---|
| `CreationTime` | `0x10` | `long` | `"cT"` |
| `Name` | `0x18` | `string` | `"n"` |
| `IndicesAndRules` | `0x20` | `List<JackarooCustomRuleSaveData>` | `"ir"` |

`JackarooCustomRuleSaveData`: `int Index` → `"I"` · `int SaveValue` → `"V"`.
(الثوابت من `JackarooCustomRulesConstants` و`JackarooCustomRulesSaveDataConstants`.)

> ⭐ المفاتيح مختصرة إلى حرف أو حرفين — نفس اقتصاد النطاق المعتمد في
> [بروتوكول جاكارو](../jackaroo-spec/05-البروتوكول.md)، مطبَّقًا هنا على القرص لا على الشبكة.

### إعدادات التسلسل — `.cctor` @`0x5119DAC`
```asm
bl  JsonSerializerSettings$$.ctor              ; 0x5119E44
mov w1, #1 → set_NullValueHandling             ; 0x5119E88   = Ignore
mov w1, #3 → set_DefaultValueHandling          ; 0x5119E98   = IgnoreAndPopulate
bl  System.Comparison<object>$$.ctor           ; 0x5119EE4
```
والمقارنة `<.cctor>b__32_0` @`0x5119FA8` تقرأ الحقل `0x10` من كلا الطرفين وتقارن
`y.CreationTime.CompareTo(x.CreationTime)` (الطرف الثاني أوّلًا @`0x5119FB8`)
⇒ **ترتيب تنازليّ: الأحدث أوّلًا**.

> ⭐ `NullValueHandling.Ignore` + `DefaultValueHandling.IgnoreAndPopulate` معًا يعنيان:
> كل قاعدة قيمتها الافتراضيّة **لا تُكتَب في الملفّ إطلاقًا**، وتُعاد من الافتراضيّ عند القراءة.
> ملفّ حفظة بقاعدة واحدة معدَّلة يحتوي مدخلًا واحدًا في `"ir"`.
> ⚠️ ولازمه أنّ **تغيير القيم الافتراضيّة في نسخة لاحقة يغيّر معنى الحفظات القديمة بأثر رجعيّ.**

## ٨. خلاصة لإعادة البناء

| القرار | الواقع في الأصل | ⚠️ |
|---|---|---|
| الملفّات على القرص | **JSON صريح غير مضغوط** | الضغط مبنيّ ومعطَّل |
| خوارزميّة الضغط لو فُعِّلت | Brotli (افتراضيّ) ثم Base64 | GZip بديل متاح |
| المسار | `CachePath/{Game}/savedCustomRules/` | معزول بالبيئة والّلعبة |
| الاسم | `{Name}_{CreationTime}.json` | الحروف الممنوعة **تُحذف** |
| التحميل | `Parallel.ForEach` داخل `Task.Run` | `Monitor` حول `List.Add` إلزاميّ |
| ملفّ تالف | `LogWarning` ويُتخطّى | لا يُسقط القائمة |
| الترتيب | تنازليّ بـ`CreationTime` | بعد التحميل لا أثناءه |
| WebGL | كوروتين بديل عبر `CoroutineDummy` | `Task.Run` غير متاح هناك |
| نطاق النظام | **جاكارو فقط** | ليس نظام حفظ عامًّا مهما بدا |
